🎯 为什么值得玩

很多同学在复现实验时发现，明明设了 torch.manual_seed(42)，两次运行的 loss 却从 0.002 变成 0.0004，权重也对不上。根因是 PyTorch 的随机性来自四层：Python 内置 random、NumPy、PyTorch CPU/GPU、CUDA 底层，只设一层等于没锁全。本教程带你用「四层种子 + 算法开关」实现逐位可复现，适合论文复现、调参对比、CI 回归测试等场景。

📝 一步步教你做

1

第1步：写一个可复现种子函数，一次锁四层

新建 seed_everything.py，定义函数 set_seed(seed=42)：先 import random, numpy as np, torch；依次执行 random.seed(seed)、np.random.seed(seed)、torch.manual_seed(seed)、torch.cuda.manual_seed_all(seed)。这样 Python、NumPy、PyTorch CPU、PyTorch 所有 GPU 的随机源都被固定。
💡 小贴士：torch.cuda.manual_seed_all 要放在 torch.manual_seed 之后，且即使没有 GPU 也建议保留，方便代码迁移。
2

第2步：打开 cudnn 确定性开关，锁住算法层

在 set_seed 里继续加两行：torch.backends.cudnn.deterministic = True 和 torch.backends.cudnn.benchmark = False。前者强制 cuDNN 使用确定性算法，后者关闭自动调优以避免不同运行选到不同算法。这是第五层「算法非确定性」的开关。
💡 小贴士：开启 deterministic 后部分算子会变慢，训练速度可能下降 5%-20%，复现优先时再开。
3

第3步：在训练脚本入口第一时间调用

在 train.py 的 import 之后、任何模型/数据创建之前调用 set_seed(42)。注意 DataLoader 的 worker 也要设种子：给 DataLoader 传 worker_init_fn=lambda worker_id: np.random.seed(42 + worker_id)，并设 generator=torch.Generator().manual_seed(42)。
💡 小贴士：如果用了多进程 DataLoader，不设 worker_init_fn 的话每个 epoch 的数据顺序仍可能不同。
4

第4步：双跑对比验证逐位一致

写一个最小训练脚本：固定随机数据、两层线性模型、固定学习率，跑 10 个 step 后打印 loss 和第一层权重。连续运行两次，把输出保存到 log1.txt 和 log2.txt，用 diff 命令对比。若完全一致，说明四层种子 + 开关生效。
💡 小贴士：对比时建议打印权重的前 5 个元素，比只看 loss 更能暴露细微差异。
5

第5步：排查仍不一致的残留因素

如果 diff 仍有差异，依次检查：是否用了非确定性算子（如 torch.nn.functional.interpolate 的某些模式）、是否开了 TF32（设 torch.backends.cuda.matmul.allow_tf32 = False）、是否用了随机增强且未设种子、是否多卡 DDP 未设 torch.distributed 种子。逐项关闭后重跑对比。
💡 小贴士：PyTorch 官方有 reproducibility 文档，列出所有非确定性算子，遇到怪问题先查表。

✨ 完成后你会得到

两次运行输出的 loss 和权重逐位一致（diff 无输出），loss 不再从 0.002 跳到 0.0004。在 CPU 和单卡 GPU 上均可复现；多卡场景需额外设 DDP 种子，但四层种子 + cudnn 开关已覆盖绝大多数单机实验。

❓ 常见问题

只设 torch.manual_seed 为什么不够？ ▼
因为 PyTorch 的随机数还来自 Python random、NumPy 和 CUDA 底层，只设 torch 层等于只锁了一扇门，其他三扇仍会引入随机性。
开了 deterministic 训练变慢怎么办？ ▼
复现实验时开启，正式训练可关闭；也可只对需要对比的 epoch 开启，或用环境变量按需切换。
多卡 DDP 怎么保证可复现？ ▼
除四层种子外，还要在每张卡上设 torch.cuda.manual_seed_all，并给 torch.distributed 设种子；数据切分也要固定。
为什么两次 loss 一样但权重有微小差异？ ▼
可能是 TF32 或非确定性算子导致，检查 torch.backends.cuda.matmul.allow_tf32 并关闭，再排查 interpolate 等算子。
CPU 上需要设 cudnn 开关吗？ ▼
不需要，cudnn 只影响 GPU；但保留代码无副作用，方便同一脚本在 CPU/GPU 间切换。

🚀 进阶玩法

  • 🔹 变体1：把 set_seed 封装成装饰器，自动包裹训练函数，避免忘记调用。

  • 🔹 变体3：在 Hydra/OmegaConf 配置里加 seed 字段，启动时统一注入，适合多实验管理。
