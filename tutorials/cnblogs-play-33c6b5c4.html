🎯 为什么值得玩

过去我们让模型输出结构化结果，通常靠提示词要求它写 JSON，再解析文本。但这种方式容易受格式错误、幻觉影响。Jev 模式把决策问题还原成有边界的概率读取——模型只负责给出候选 token 的概率分布，我们直接从 logits 里选答案。vLLM 率先支持这种思路，TensorSharp 则在 .NET 生态里走通了这条路。如果你正在用 C# 做本地推理，现在一条 HTTP 请求或一个 JevAsync 调用就能完成。

  • 一个本地或远程推理服务（如 vLLM） → 访问

📝 一步步教你做

1

第1步：创建 .NET 控制台项目并安装 TensorSharp

打开终端，执行 dotnet new console -n JevDemo，进入目录后运行 dotnet add package TensorSharp。如果你用的是本地推理服务，还需要添加 Microsoft.Extensions.Http 包以便发送 HTTP 请求。确保项目能正常还原依赖。
💡 小贴士：建议使用 .NET 8，因为 TensorSharp 对最新版有更好的异步支持。
2

第2步：准备推理服务并确认 Jev 模式可用

启动 vLLM 服务，例如 python -m vllm.entrypoints.openai.api_server --model Qwen/Qwen2.5-7B-Instruct --enable-logprobs。注意要开启 logprobs 支持，否则无法读取 logits。然后用 curl 测试 /v1/completions 接口，确认返回中包含 logprobs 字段。
💡 小贴士：如果使用 TensorSharp 自带的本地推理，直接调用 JevAsync 即可，无需额外启动服务。
3

第3步：编写 Jev 请求，指定候选 token 和边界

在 Program.cs 中，构造一个请求对象，包含 prompt、候选答案列表（如 ["是", "否"]）以及要读取的 top_logprobs 数量。调用 TensorSharp 的 JevAsync 方法，传入模型名称和请求参数。代码示例：var result = await client.JevAsync(model, prompt, new[] { "是", "否" });
💡 小贴士：候选 token 尽量用单个 token 表示，避免分词差异导致概率读取错误。
4

第4步：从返回的 logits 中直接读取决策

JevAsync 返回一个字典，键是候选 token，值是对应的概率或 logit 值。你只需要取概率最高的那个作为决策。例如：var decision = result.OrderByDescending(x => x.Value).First().Key; 这样就完成了一次去噪读取，不需要解析任何 JSON 文本。
💡 小贴士：可以设置一个阈值，当最高概率低于 0.6 时视为不确定，触发回退逻辑。
5

第5步：集成到实际业务并验证效果

把上述逻辑封装成一个服务类，注入到你的 ASP.NET Core 控制器或后台任务中。用几个测试用例验证：比如情感分类、意图识别、是否回答。对比传统 JSON 提示词方式，观察准确率和延迟变化。通常 Jev 模式能减少 30% 以上的输出 token 并消除格式错误。
💡 小贴士：记录每次决策的概率分布，方便后续做阈值调优和监控。

✨ 完成后你会得到

程序运行后，控制台输出类似「决策：是，概率：0.92」的结果。没有 JSON 解析步骤，也没有格式异常。在业务系统中，你可以直接拿到布尔值或枚举值，响应速度更快，且不会因为模型多写了一个逗号而崩溃。

❓ 常见问题

Jev 模式和普通 logprobs 有什么区别？ ▼
普通 logprobs 只是返回 token 概率，Jev 模式进一步把决策问题建模成有边界的概率读取，并封装了候选 token 的映射和选择逻辑，开箱即用。
必须用 vLLM 吗？TensorSharp 能独立运行吗？ ▼
不必须。TensorSharp 本身支持本地推理，也可以连接任何兼容 OpenAI API 且支持 logprobs 的服务，vLLM 只是其中一种常见选择。
候选 token 如果被分词成多个 token 怎么办？ ▼
尽量选择单 token 的候选词。如果无法避免，可以取第一个 token 的概率作为近似，或者使用 TensorSharp 提供的 token 对齐工具。
Jev 模式支持多分类吗？ ▼
支持。候选列表可以包含多个选项，JevAsync 会返回每个选项的概率，你取最大值即可。注意候选数量不要超过 top_logprobs 的限制。
性能比 JSON 提示词快多少？ ▼
通常快 20%-50%，因为不需要生成完整的 JSON 文本，只读取几个 token 的 logits。具体取决于模型和候选数量。

🚀 进阶玩法

  • 🔹 变体1：用 Jev 模式做多标签分类——候选列表设为所有标签，取概率超过阈值的多个标签作为输出。
  • 🔹 变体2：结合缓存机制——对相同 prompt 的 logits 结果进行缓存，避免重复推理，适合高频决策场景。
  • 🔹 变体3：在 Jev 基础上加温度采样——不直接取 argmax，而是按概率分布采样，用于需要多样性的决策任务。

💡 一句话总结

Jev 模式的精髓是把「让模型写答案」变成「从概率里读答案」，一次去噪，直接拿到决策，又快又稳。
