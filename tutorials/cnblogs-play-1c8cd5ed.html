🎯 为什么值得玩

很多开发者遇到 PyTorch 或 TensorFlow 检测不到 GPU 时，第一反应是重装驱动，结果折腾半天发现是装了 CPU 版轮子。更隐蔽的是 CUDA_VISIBLE_DEVICES 被设成 -1，程序零报错但 GPU 凭空消失。这个玩法把 GPU 不可用问题按概率排序分三层排查，用一条 cuda_doctor 命令快速定断点，避免盲目重装驱动浪费时间。

  • PyTorch 或 TensorFlow → 访问

  • NVIDIA 驱动与 CUDA Toolkit → 访问
    驱动层排查需要 nvidia-smi 和 nvcc
  • cuda_doctor 脚本 → 访问

📝 一步步教你做

1

第1步：准备 cuda_doctor 检测脚本

新建一个 cuda_doctor.py 文件，写入检测逻辑：先打印 torch.__version__ 和 torch.version.cuda 判断是否 CPU 轮子；再读取 os.environ.get('CUDA_VISIBLE_DEVICES') 检查是否被设为 -1；最后调用 subprocess 执行 nvidia-smi 和 nvcc --version 验证驱动层。保存后在终端运行 python cuda_doctor.py。
💡 小贴士：如果不想自己写，可直接参考原文博客中的脚本片段，复制后按需修改。
2

第2步：检查框架层是否装了 CPU 轮子

运行脚本后看第一段输出：如果 torch.version.cuda 为 None 或空，说明装的是 CPU 版 PyTorch。此时执行 pip list | grep torch 确认版本，然后卸载重装对应 CUDA 版本的轮子，例如 pip install torch --index-url https://download.pytorch.org/whl/cu118。
💡 小贴士：这是最常见的原因，占 GPU 不可用问题的一半以上，优先排查。
3

第3步：检查 CUDA_VISIBLE_DEVICES 环境变量

看脚本第二段输出：如果 CUDA_VISIBLE_DEVICES 被设为 -1，GPU 会被隐藏且零报错。在终端执行 echo $CUDA_VISIBLE_DEVICES 确认，若为 -1 则用 export CUDA_VISIBLE_DEVICES=0 临时恢复，或检查 .bashrc、.zshrc、Dockerfile 中是否写死了 -1。
💡 小贴士：这个坑最隐蔽，因为程序不会报错，只是 torch.cuda.is_available() 返回 False。
4

第4步：检查驱动层 nvidia-smi 与 nvcc

看脚本第三段输出：如果 nvidia-smi 报错或找不到命令，说明驱动没装好或 GPU 未挂载。先运行 nvidia-smi 看是否能列出 GPU，再运行 nvcc --version 确认 CUDA Toolkit 版本。若 nvidia-smi 正常但 nvcc 缺失，安装对应 CUDA Toolkit 即可。
💡 小贴士：驱动层放最后排查，因为重装驱动成本最高，前面两层能解决大部分问题。
5

第5步：验证修复结果

按断点修复后，重新运行 python cuda_doctor.py，确认三层全部通过。再执行 python -c "import torch; print(torch.cuda.is_available(), torch.cuda.device_count())" 应输出 True 和大于 0 的数字。最后跑一个小张量到 GPU 上验证实际可用。
💡 小贴士：验证时用 torch.randn(1).cuda() 做一次真实运算，比只看 is_available() 更可靠。

✨ 完成后你会得到

cuda_doctor 输出显示框架层 CUDA 版本正常、CUDA_VISIBLE_DEVICES 未设为 -1、nvidia-smi 和 nvcc 均可执行，torch.cuda.is_available() 返回 True，GPU 可正常用于训练和推理。

❓ 常见问题

cuda_doctor 命令是官方工具吗？ ▼
不是，它是社区脚本或自定义检测脚本，核心是把三层排查逻辑串起来，可自行编写或从原文获取。
torch.version.cuda 有值但 is_available() 仍为 False 怎么办？ ▼
重点查 CUDA_VISIBLE_DEVICES 是否被设为 -1，以及驱动版本是否低于框架要求的 CUDA 版本。
nvidia-smi 正常但 nvcc 找不到怎么办？ ▼
说明驱动装了但 CUDA Toolkit 没装或没加进 PATH，安装对应版本 Toolkit 并配置环境变量即可。
Docker 容器里 GPU 不可用怎么排查？ ▼
先确认启动时加了 --gpus all，再在容器内跑 cuda_doctor，重点看 CUDA_VISIBLE_DEVICES 和设备挂载情况。
重装驱动能解决所有问题吗？ ▼
不能，驱动层只是第三层，框架层 CPU 轮子和环境变量 -1 更常见，盲目重装驱动往往白费功夫。
