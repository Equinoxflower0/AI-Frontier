传统上让大模型做批量决策需要反复调用 API 或写复杂提示词，效率低且结果格式不稳定。Gemini Decisions API 专门为「多问题、快决策」设计，支持一次请求传入多个问题并返回结构化 JSON，官方实测 100 个问题仅需 0.41 秒。它适合内容审核、工单分类、问卷编码、商品标签等需要大批量判断的业务。本教程带你从零跑通这个工具链，并给出可复用的提示词模板。

📝 一步步教你做

1

第1步：在 AI Studio 创建 API Key 并确认模型名

登录 Google AI Studio，点击左侧「Get API key」创建密钥并保存。然后在模型列表中确认可用的 Decisions 模型名称（如 gemini-decisions-001 或官方文档标注的版本号）。建议先在 AI Studio 的 Chat 界面用一句简单决策问题测试模型是否可用。
💡 小贴士：API Key 只显示一次，务必立即复制到密码管理器；免费额度有限，批量测试时先用 10 条以内的小样本。
2

第2步：安装 SDK 并写最小可运行脚本

在终端执行 pip install google-generativeai 安装官方 SDK。新建 decide.py，用 genai.configure(api_key=...) 配置密钥，然后调用 genai.GenerativeModel('模型名').generate_content() 传入一个决策问题。运行后确认能拿到返回文本，再进入批量模式。
💡 小贴士：如果报 404 模型不存在，回到第1步核对模型名；建议把模型名写成变量，方便后续切换版本。
3

第3步：构造批量决策请求体（核心提示词模板）

Decisions API 的关键是把多个问题组织成结构化输入。推荐模板：先写系统指令「你是一个批量决策引擎，对每个问题只输出 JSON 数组，每项包含 id、decision（yes/no 或类别）、confidence（0-1）、reason（不超过20字）」，再把 100 个问题以 JSON 数组形式放入用户消息。确保每个问题带唯一 id，方便回填结果。
💡 小贴士：提示词里明确「只输出 JSON、不要解释」，可大幅减少解析失败；问题数量先控制在 20 条调试，稳定后再扩到 100 条。
4

第4步：发送请求并解析结构化结果

用 generate_content 一次性提交包含全部问题的请求，设置 temperature=0 保证决策稳定。拿到响应后，用 json.loads 解析返回文本，按 id 与原始问题做映射。如果解析失败，打印原始返回并检查模型是否多加了 Markdown 代码块，必要时用正则剥离。
💡 小贴士：在请求里加 response_mime_type='application/json'（若模型支持）可强制返回纯 JSON，省去清洗步骤。
5

第5步：批量跑通并记录耗时

用 time.perf_counter() 包住请求前后，记录 100 个问题的总耗时。对照官方 0.41 秒的基准，检查自己的网络与模型版本差异。把结果写入 CSV（id、问题、决策、置信度、理由），方便业务方复核。
💡 小贴士：置信度低于 0.6 的条目建议人工抽检，这是批量决策落地的安全阀。

❓ 常见问题

Decisions API 和普通 Gemini 对话接口有什么区别？ ▼
它针对「多问题批量决策」优化，一次请求可传入大量问题并返回结构化结果，延迟更低、格式更稳定，适合分类/筛选类任务而非开放式聊天。
免费额度够跑 100 个问题吗？ ▼
AI Studio 免费层有每分钟/每天的请求次数限制，单次 100 问通常只算一次请求，额度内可跑；具体限额以官方定价页为准，批量生产建议升级付费层。
返回的不是合法 JSON 怎么办？ ▼
先检查提示词是否明确「只输出 JSON」，再尝试设置 response_mime_type 为 application/json；仍失败时用正则提取第一个 [ 到最后一个 ] 之间的内容再解析。
决策结果不稳定、每次不一样怎么办？ ▼
把 temperature 设为 0，并在提示词中固定决策标准和输出格式；对关键业务可跑两次取一致结果，不一致的条目转人工。
可以处理中文问题吗？ ▼
可以，Gemini 多语言能力较好；建议在提示词中指定「用中文输出 reason」，并保持问题表述简洁、标准统一。
