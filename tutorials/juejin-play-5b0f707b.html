🎯 为什么值得玩

Postman - REST Client 是一款经典的 Chrome 扩展，基于原生 JavaScript + jQuery 实现，可直接在浏览器标签页中调试 REST API。但随着技术发展，老版本在功能、界面和安全性上逐渐落后。本教程借助 AI 能力，通过提示词和工具链，对老插件进行现代化改造，适合想学习 AI 辅助开发、工具链整合的开发者。整个过程难度低，只需基本的前端知识即可完成。

第1步：获取并解压老版 Postman 插件

从 Chrome 应用商店安装 Postman - REST Client，或下载 crx 文件后改后缀为 zip 解压。将解压后的文件夹放入工作目录，用 VS Code 打开，观察其文件结构（manifest.json、js、css 等）。
💡 小贴士：如果从商店安装，可在 chrome://extensions 开启开发者模式，点击“打包扩展程序”获取 crx。
2

第2步：用 AI 分析代码结构与升级点

将 manifest.json 和主要 JS 文件内容粘贴给 AI 助手，提示词示例：“分析这个 Chrome 扩展的代码结构，列出可升级的技术点（如 jQuery 替换、Manifest V3 迁移、UI 现代化）”。根据 AI 输出，确定优先升级项，比如将 jQuery 替换为原生 fetch API。
💡 小贴士：让 AI 生成升级清单表格，按优先级排序，避免一次性改动过多。
3

第3步：生成现代化代码替换老逻辑

针对每个升级点，用 AI 生成替换代码。例如提示：“将这段 jQuery AJAX 请求改写为原生 fetch，并添加 async/await 和错误处理”。将生成的代码复制到对应文件中，注意保留原有功能逻辑。
💡 小贴士：每次只替换一个模块，替换后立即在浏览器中加载扩展测试，确保功能正常。
4

第4步：迁移到 Manifest V3 并优化权限

用 AI 辅助将 manifest.json 从 V2 升级到 V3，修改 background 脚本为 service worker，调整权限声明。提示词：“将以下 Manifest V2 配置转换为 V3，并说明注意事项”。根据 AI 建议修改后，在 chrome://extensions 中重新加载扩展。
💡 小贴士：V3 对远程代码执行限制更严，确保所有 JS 都本地打包，不要动态加载外部脚本。
5

第5步：测试与调试升级后的插件

在浏览器中打开扩展页面，测试 GET/POST 请求、历史记录、环境变量等核心功能。利用 Chrome DevTools 查看 console 报错，将错误信息反馈给 AI 获取修复建议。反复迭代直到所有功能正常。
💡 小贴士：让 AI 生成一份测试用例清单，逐项勾选验证，避免遗漏。
