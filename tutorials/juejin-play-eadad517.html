用AI裁判重构编程工作流

🎯 为什么值得玩

很多开发者写代码时习惯直接上手，结果方案没想透、边界没理清，写到一半才发现方向错了。掘金这篇实战教程提出用 AI 裁判重构工作流：把开发拆成背景、方案、实现、审查、验证五个阶段，每个阶段结束让 AI 按预设标准判定是否通过，不通过就退回上一阶段。这套结构适合 dev-workflow，也能迁移到 bugfix 等场景，尤其适合独立开发者或小团队在没有 Code Review 的情况下保证质量。

🧰 你需要准备

  • ChatGPT / Claude / DeepSeek → 访问
    作为 AI 裁判，负责按标准判定每个 Gate 是否通过
  • Cursor 或 VS Code + Copilot → 访问
    在编辑器内直接调用 AI 裁判，减少切换成本
  • Notion / Obsidian / 飞书文档 → 访问
    记录每个阶段的产出和裁判结论，形成可追溯的工作流日志
  • Git → 访问
    用分支或 commit 标记每个 Gate 的通过点，方便回滚

📝 一步步教你做

1

第1步：定义五阶段工作流与 Gate 标准

在文档中写下五个阶段：背景（为什么做）、方案（怎么做）、实现（写代码）、审查（代码质量）、验证（测试通过）。为每个阶段写一条明确的 Gate 通过标准，例如「背景阶段必须包含用户场景和验收条件」「方案阶段必须列出至少两个备选方案及取舍理由」。把这些标准整理成一段 prompt 模板，后续每次让 AI 裁判按此判定。
💡 小贴士：Gate 标准要可量化，避免「方案合理」这种模糊表述，改成「方案包含数据流图和异常处理说明」。
2

第2步：让 AI 裁判执行背景 Gate

把需求描述和背景文档发给 AI，附上第1步的 Gate 标准，要求它输出「通过/不通过 + 缺失项清单」。如果不通过，按缺失项补充背景文档，再次提交裁判，直到通过。通过后把结论记录到工作流日志，并打一个 Git tag 如 gate-1-pass。
💡 小贴士：可以让 AI 裁判同时扮演「挑剔的产品经理」，主动追问边界场景，逼你把背景想全。
3

第3步：方案 Gate 与实现 Gate 串联

背景通过后，让 AI 生成或你手写技术方案，提交给 AI 裁判按方案 Gate 标准判定。方案通过后再进入编码，编码完成后把 diff 或关键代码片段发给裁判，按实现 Gate 标准检查是否覆盖方案中的每个点。两个 Gate 都通过才允许进入审查阶段。
💡 小贴士：实现 Gate 可以要求 AI 对照方案逐条打勾，输出「方案点 → 代码位置」的映射表，漏掉的一目了然。
4

第4步：审查 Gate 与验证 Gate 收尾

审查阶段让 AI 裁判按代码规范、安全、性能三个维度打分，低于阈值则退回实现阶段。验证阶段把测试用例和运行结果发给裁判，确认验收条件全部满足。全部通过后合并代码，并在日志中记录五个 Gate 的通过时间与裁判结论。
💡 小贴士：审查 Gate 可以固定用同一段 prompt，保证每次评判标准一致，避免 AI 随机发挥。
5

第5步：沉淀为可复用的 prompt 模板库

把五个 Gate 的 prompt 分别保存为模板文件，变量部分用占位符（如 {{需求描述}}、{{代码diff}}）。下次新任务直接套模板，只需替换变量。可以进一步把模板接入 Cursor 的 Rules 或自定义指令，实现一键调用。
💡 小贴士：模板库按项目类型分目录，dev-workflow 和 bugfix-workflow 各一套，复用率更高。

✨ 完成后你会得到

每个开发任务都有五个 Gate 的通过记录，代码返工率明显下降；AI 裁判输出的缺失项清单成为改进依据；prompt 模板库可复用于后续任务，形成个人或团队的标准化工作流。

❓ 常见问题

AI 裁判会不会太宽松，什么都给通过？ ▼
把 Gate 标准写成可量化的检查项，并要求 AI 输出「逐项打勾 + 缺失项」，宽松问题会大幅缓解；也可以让 AI 先扮演反方挑刺再判定。
每个 Gate 都调用 AI 会不会很慢？ ▼
背景和方案 Gate 可以合并成一次对话完成；实现和审查 Gate 可以批量提交 diff。实际多花的时间远小于返工成本。
没有测试用例怎么做验证 Gate？ ▼
让 AI 裁判根据背景阶段的验收条件生成测试用例草稿，人工确认后执行，再把结果交给裁判判定。
这套流程适合多大的任务？ ▼
适合半天到三天规模的功能开发或 bugfix；太小的改动可以只保留方案和审查两个 Gate。

🚀 进阶玩法

  • 🔹 变体1：bugfix-workflow——把五阶段改为「复现→根因→修复→回归」，Gate 标准侧重复现步骤完整性和回归用例覆盖。
  • 🔹 变体2：双裁判模式——用两个不同模型（如 GPT 和 Claude）分别判定同一 Gate，结论不一致时人工介入，降低单模型偏差。
  • 🔹 变体3：CI 集成——把审查 Gate 的 prompt 封装成脚本，在 Git pre-push hook 中自动运行，不通过则阻止推送。
