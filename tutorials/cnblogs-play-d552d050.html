🎯 为什么值得玩

chat-demo 是 DeepSeek 官方放出的静态聊天示例，没有后端、没有会话库，浏览器直接拿着你的 API Key 去请求你配置的服务。它小到可以一下午读完全部逻辑，又完整到把流式、思考、搜索、引用、附件、语音、分支、导入导出全做了一遍。如果你的目标是接一套对话产品，它是一份极佳的参考实现；如果你只想学 API 用法，它比文档更直观。本教程带你从零跑通这个 demo，并拆解核心代码，让你能举一反三。

📝 一步步教你做

1

第1步：获取源码并安装依赖

打开终端，执行 git clone https://github.com/deepseek-ai/chat-demo.git（若仓库地址变动，请参考博客园原文中的链接）。进入目录后运行 npm install 安装依赖。然后用 npm run dev 启动本地开发服务器，浏览器访问终端提示的地址（通常是 http://localhost:5173）。
💡 小贴士：如果 npm install 慢，可切换淘宝镜像：npm config set registry https://registry.npmmirror.com
2

第2步：配置 API Key 与请求地址

在项目根目录找到 .env 或 config 文件（不同版本可能不同），填入你的 DeepSeek API Key。同时确认请求的 base URL 指向 https://api.deepseek.com。保存后重启开发服务器。注意：demo 是纯前端，API Key 会暴露在浏览器中，仅限本地学习使用。
💡 小贴士：不要把带 Key 的代码推送到公开仓库；建议用 .env.local 并加入 .gitignore。
3

第3步：跑通基础对话与流式输出

在聊天框输入“你好”，观察浏览器 Network 面板中的请求。你会看到 POST /chat/completions 请求，且响应是 stream 形式（text/event-stream）。阅读 src/api/chat.js 或类似文件，理解如何用 fetch + ReadableStream 逐块解析 SSE 数据并更新 UI。
💡 小贴士：在 Network 面板勾选“EventStream”标签，可以直观看到每个 chunk 的内容。
4

第4步：拆解思考、搜索与引用功能

在输入框上方找到“深度思考”和“联网搜索”开关。打开后发问，观察请求体中多了 reasoning 或 search 相关参数。阅读对应组件代码，理解如何将模型返回的 reasoning_content 和 citations 字段渲染到界面上。引用通常以角标形式展示，点击可跳转来源。
💡 小贴士：搜索功能依赖后端代理，demo 中可能用模拟数据；重点看请求参数和渲染逻辑，而非真实搜索。
5

第5步：体验附件、语音、分支与导入导出

尝试上传一张图片或 PDF，观察请求如何将文件转为 base64 或 multipart 发送。点击麦克风按钮测试语音输入（依赖浏览器 Web Speech API）。在消息上右键或点击按钮创建分支，理解会话树的数据结构。最后使用导出按钮将对话保存为 JSON 或 Markdown。
💡 小贴士：分支功能的核心是维护一个树形消息列表，每个节点有 parentId；阅读 store 或 reducer 代码即可掌握。
6

第6步：修改源码并验证自定义功能

尝试修改系统提示词（system prompt）或默认模型参数（如 temperature）。例如在请求体中加入 system: '你是一个幽默的助手'，刷新后观察回复风格变化。再修改流式渲染的节流逻辑，让打字机效果更快或更慢。通过小改动验证你对代码的理解。
💡 小贴士：用 VS Code 的调试功能在关键函数打断点，比 console.log 更高效。

❓ 常见问题

没有 DeepSeek API Key 能跑吗？ ▼
不能真实调用模型，但可以修改代码指向兼容 OpenAI 接口的本地模型（如 Ollama），或使用 mock 数据学习前端逻辑。
为什么我的请求报 401 错误？ ▼
检查 API Key 是否填写正确、是否有多余空格，以及请求头 Authorization 是否为 Bearer <key>。
demo 中的联网搜索是真实的吗？ ▼
官方 demo 可能仅演示参数传递和 UI 渲染，真实搜索需要你自行接入搜索 API 并在后端代理，避免前端暴露 Key。
分支功能的数据结构是怎样的？ ▼
通常是一个消息树，每个消息有 id 和 parentId，当前分支由当前选中节点回溯到根节点决定。阅读 store 中的 addMessage 和 switchBranch 即可理解。
如何部署到线上？ ▼
由于是纯前端且含 API Key，不建议直接部署。正确做法是加一个轻量后端代理（如 Node.js/Express）转发请求并隐藏 Key，前端只与代理通信。
