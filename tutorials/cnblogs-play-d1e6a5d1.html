🎯 为什么值得玩

很多开发者习惯用 Codex GUI 或 Electron 版 GUI Agent，但多项目并行时窗口分散、内存占用高，电脑很快扛不住。这个玩法用 Avalonia 跨平台框架 + .NET 构建一个 CLI 风格的 Agent 托管面板，把多个 Agent 的启动、日志、状态集中在一个轻量界面里，资源占用远低于 Electron，适合需要同时跑多个 Agent 的开发者。

📝 一步步教你做

1

第1步：创建 Avalonia 项目骨架

打开终端执行 dotnet new install Avalonia.Templates 安装模板，然后 dotnet new avalonia.mvvm -o AgentHub 创建 MVVM 项目。进入目录后 dotnet run 确认空白窗口能正常启动。
💡 小贴士：项目名不要用中文或空格，避免后续路径问题。
2

第2步：设计 Agent 托管数据模型

在 Models 文件夹新建 AgentProcess.cs，定义属性：Id、Name、Command、Arguments、WorkingDirectory、Status、Output。再建一个 AgentManager 服务类，用 ObservableCollection<AgentProcess> 保存所有 Agent，并用 Process 类启动 CLI 进程、异步读取 StandardOutput 和 StandardError。
💡 小贴士：读取输出时用 BeginOutputReadLine 事件，避免阻塞 UI 线程。
3

第3步：构建主界面布局

在 MainWindow.axaml 中用 Grid 分两栏：左侧 ListBox 绑定 Agent 列表，显示名称和状态；右侧用 TextBox 只读显示选中 Agent 的实时输出，底部放“启动/停止/清空”按钮。用 Avalonia 的 Binding 把按钮命令绑定到 ViewModel 的 RelayCommand。
💡 小贴士：输出区域设置 TextWrapping="NoWrap" 和 ScrollViewer，方便查看长日志。
4

第4步：实现进程启动与日志实时刷新

在 ViewModel 中实现 StartAgent 命令：根据选中 Agent 的 Command 和 Arguments 创建 ProcessStartInfo，设置 RedirectStandardOutput=true、UseShellExecute=false，启动进程后把输出追加到该 Agent 的 Output 属性。用 Dispatcher.UIThread.Post 确保 UI 更新在主线程执行。
💡 小贴士：给每个 Agent 加一个 CancellationTokenSource，停止时先 Kill 进程再取消读取。
5

第5步：批量管理与状态监控

在界面顶部加“全部启动”“全部停止”按钮，遍历 AgentManager 中所有 Agent 执行对应命令。用定时器或 Process.Exited 事件更新每个 Agent 的 Status（运行中/已停止/异常），并在 ListBox 中用颜色区分状态。
💡 小贴士：异常退出时记录 ExitCode，方便排查 Agent 崩溃原因。
6

第6步：打包与日常使用

执行 dotnet publish -c Release -r win-x64 --self-contained 生成独立可执行文件，复制到常用目录。日常使用时把不同项目的 Agent 配置保存为 JSON，启动工具后一键加载，所有 Agent 日志集中在一个窗口查看。
💡 小贴士：配置文件放在用户目录下，避免每次更新程序时被覆盖。

✨ 完成后你会得到

打开 AgentHub 后，左侧列出多个 Agent 及状态，点击“全部启动”后各 Agent 并行运行，右侧实时滚动显示选中 Agent 的日志，内存占用明显低于 Electron 方案，几十个 Agent 同时运行也不卡顿。

❓ 常见问题

必须用 .NET 8 吗？ ▼
建议用 .NET 8 LTS，Avalonia 11 对 .NET 6/7/8 都支持，但新项目优先选 LTS 以获得长期维护。
CLI Agent 的输出中文乱码怎么办？ ▼
在 ProcessStartInfo 中设置 StandardOutputEncoding = Encoding.UTF8，并确保 Agent 本身输出 UTF-8。
可以托管非 CLI 的 GUI Agent 吗？ ▼
这个工具核心是管理命令行进程，GUI Agent 需要额外做窗口嵌入或自动化，不适合直接套用。
如何让 Agent 在后台持续运行？ ▼
启动进程时不要设置 CreateNoWindow=false，并保持主程序不退出；也可以把 Agent 注册为系统服务，但那就超出本工具范围了。
Avalonia 和 WPF 有什么区别？ ▼
Avalonia 跨平台（Windows/Linux/macOS），渲染自绘，不依赖系统控件；WPF 仅 Windows。做跨平台托管工具选 Avalonia 更合适。
