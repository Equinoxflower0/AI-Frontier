📝 一步步教你做

1

第1步：克隆清单并建立工具链地图

执行 git clone https://github.com/ai-boost/awesome-harness-engineering 并打开 README。按清单分类（tools、patterns、evals、memory、MCP、permissions、observability、orchestration）在本地新建 toolchain.md，每类先各选 1 个候选工具，标注官网和许可证。不要贪多，先保证每类有且仅有一个主选。
💡 小贴士：用 VS Code 的 Markdown 预览边看清单边填表，避免遗漏分类。
2

第2步：搭建提示词与编排层

从清单的 patterns 和 orchestration 分类中选一个编排框架（如 LangGraph 或 CrewAI），按官方 quickstart 跑通一个两节点 Agent。把系统提示词抽成独立 prompt 模板文件，用变量占位符管理。在本地跑通一次「输入→规划→执行→输出」的最小闭环。
💡 小贴士：提示词模板用 Jinja2 或 f-string 均可，关键是版本化，建议放进 Git。
3

第3步：接入记忆与 MCP 工具

从 memory 分类选一个向量记忆方案（如 Chroma 或 Qdrant），按文档启动本地实例。再从 MCP 分类选一个官方 MCP Server，用 Docker 跑起来并在编排框架中注册。让 Agent 能调用一个外部工具并把结果写入记忆，验证读写链路。
💡 小贴士：MCP Server 先用官方示例，跑通后再换自定义工具，降低排错成本。
4

第4步：加上评估与权限护栏

从 evals 分类选一个评估框架（如 Ragas 或 DeepEval），为第2步的 Agent 写 3 条测试用例并跑分。再从 permissions 分类选一个权限方案，为工具调用加上白名单和人工确认开关。确保越权调用会被拦截并记录日志。
💡 小贴士：评估用例先覆盖正常路径和一条越权路径，后续再扩充边界用例。
5

第5步：接入可观测性并固化工具链

从 observability 分类选一个方案（如 Langfuse 或 Phoenix），用 Docker 启动并在 Agent 中接入 tracing。跑一次完整任务，在面板中查看调用链、耗时和 token 消耗。最后把 toolchain.md 补全为可复现的安装脚本和配置清单，提交到自己的仓库。
💡 小贴士：把 Docker Compose 和 .env.example 一起提交，别人 clone 后一条命令即可复现。

你拥有一个可复现的 AI Agent 工程化工具链仓库：包含编排框架、提示词模板、记忆与 MCP 工具、评估用例、权限护栏和可观测性面板。运行一条命令即可启动全套服务，并在面板中看到完整的 Agent 调用链和评估分数。

❓ 常见问题

清单里工具太多，如何选择？ ▼
按分类每类只选一个主选，优先选 Star 多、文档全、有 Docker 镜像的，跑通后再替换。
没有 GPU 能跑吗？ ▼
可以。记忆和可观测性组件用 CPU 即可，LLM 可调用云端 API，本地只跑编排和工具层。
MCP 和普通工具调用有什么区别？ ▼
MCP 是标准化协议，工具可跨 Agent 复用；普通调用是框架内私有实现，迁移成本更高。
评估框架必须现在就加吗？ ▼
建议尽早加，哪怕只有 3 条用例，也能防止后续改动导致回归。
这套工具链能直接上生产吗？ ▼
作为起点可以，但生产还需补充密钥管理、限流、审计和灰度发布等环节。

🚀 进阶玩法

  • 🔹 变体1：只搭最小可观测链路——跳过记忆和评估，专注编排+权限+Langfuse，适合快速验证想法。
  • 🔹 变体2：以 MCP 为中心——先搭 3 个 MCP Server，再用编排框架串联，适合工具型 Agent。
  • 🔹 变体3：评估驱动开发——先写 10 条评估用例，再倒推选工具和提示词，适合对质量要求高的场景。
