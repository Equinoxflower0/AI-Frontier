🎯 为什么值得玩

很多开发者同时用多个 AI 编码助手，但切换工具、复制粘贴、跨设备同步非常麻烦。Octopus 是一个基于 .NET 10 + Avalonia 12 + NativeAOT 编译的开源跨平台工作台，内置 61 款智能体（49 款支持 ACP 图形界面与真终端一键切换），还带 MCP 跨机协作总线和 Bot 群组连接器。它适合需要多智能体协同、远程终端操作、手机语音接入的开发者，尤其适合 Windows/macOS/Linux 多设备用户。

📝 一步步教你做

1

第1步：克隆并编译 Octopus

打开终端，执行 git clone https://github.com/octopus-ai/octopus.git 并进入目录。确认已安装 .NET 10 SDK 后，运行 dotnet restore 恢复依赖，再执行 dotnet build -c Release 编译。如果想体验 NativeAOT 原生编译，可加 -p:PublishAot=true 参数发布单文件。
💡 小贴士：首次编译时间较长，建议挂代理或配置国内 NuGet 镜像加速。
2

第2步：启动工作台并配置智能体

运行 dotnet run --project Octopus.Desktop 启动 Avalonia 图形界面。在左侧智能体面板中可以看到 61 款内置智能体，点击任意一款即可在右侧打开对话窗口。对于标注 ACP 的 49 款智能体，窗口右上角有「终端/图形」切换按钮，可随时切到真终端模式。
💡 小贴士：建议先选一个通用编码智能体（如 Codex 或 Claude 系）做连通性测试，确认 API Key 配置正确。
3

第3步：接入 MCP 跨机协作总线

在设置中打开「MCP 总线」选项，填写本机监听端口和协作机器地址。Octopus 会自动发现局域网内其他运行中的 Octopus 实例，你可以在一个界面里向另一台机器的智能体发任务。配置完成后，在智能体对话中 @ 目标机器名即可跨机调用。
💡 小贴士：跨机协作建议在同一内网或 VPN 下使用，公网暴露时务必开启 P-256 零知识加密。
4

第4步：创建 Bot 群组并连接外部工具

进入「Bot 群组」页面，点击新建群组，从 26+ 中外连接器中选择需要的服务（如 Slack、飞书、GitHub、Discord 等）。为每个连接器填入 Token 或 Webhook 地址，保存后群组内即可让多个智能体协同处理消息和任务。
💡 小贴士：连接器 Token 建议使用最小权限，避免给机器人过高的仓库或频道权限。
5

第5步：手机语音接入与远程使用

在设置中启用「手机语音接入」，Octopus 会生成一个带 P-256 零知识加密的配对二维码。用手机扫码后，即可通过语音向工作台发送编码指令，适合在通勤或离开电脑时快速触发任务。
💡 小贴士：语音指令尽量简短明确，例如「在 octopus 仓库新建 issue 并分配给 AI」，识别效果更好。

✨ 完成后你会得到

启动后能看到 Avalonia 跨平台界面，左侧列出 61 款智能体，右侧可对话并在图形/终端间切换；MCP 总线显示已连接的协作机器；Bot 群组中连接器状态为绿色；手机扫码后语音指令能正常触发任务。

❓ 常见问题

Octopus 支持哪些操作系统？ ▼
基于 Avalonia 12 和 NativeAOT，支持 Windows、macOS、Linux 三大桌面平台，编译后可发布为单文件原生程序。
必须用 .NET 10 吗？ ▼
官方要求 .NET 10 SDK，因为项目使用了 .NET 10 的新特性和 NativeAOT 改进，低版本可能编译失败。
MCP 跨机协作安全吗？ ▼
内置 P-256 零知识加密，建议只在可信内网或 VPN 中使用，公网暴露时务必开启加密并设置访问白名单。
49 款 ACP 智能体和普通智能体有什么区别？ ▼
ACP 智能体同时提供图形界面和真终端两种交互模式，可一键切换；普通智能体只有单一交互方式。
手机语音接入需要额外装 App 吗？ ▼
不需要，扫码后通过浏览器即可使用，加密通道由 Octopus 服务端生成。

🚀 进阶玩法

  • 🔹 变体1：只做本地多智能体对比——不接 MCP 和 Bot 群组，用 Octopus 同时开 3-5 个智能体对同一段代码做 review，横向比较输出质量。
  • 🔹 变体2：团队远程结对编程——两台机器都开 MCP 总线，A 机器写代码、B 机器跑测试，通过 @ 跨机调用智能体完成闭环。
  • 🔹 变体3：手机语音触发 CI 任务——把 Bot 群组接到 GitHub Actions 或飞书机器人，语音说「跑一下 main 分支测试」即可远程触发流水线。
