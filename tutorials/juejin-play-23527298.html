🎯 为什么值得玩

随着 Claude Code、Codex、Cursor 等 Agent 工具爆发，开发者往往在多个窗口间来回切换，上下文和任务状态容易混乱。T3 Code 本身不训练模型、也不自带 Agent，而是作为一个「控制台层」，把你已有的 Agent 统一接入、统一调度。它特别适合同时使用 2 个以上编程 Agent、需要并行处理多个任务、或想对比不同 Agent 输出质量的开发者。掌握这套工具链后，你可以像管理终端会话一样管理 Agent，大幅减少切换成本。

📝 一步步教你做

1

第1步：安装并初始化 T3 Code

先确保 Node.js 18+ 已就绪，然后通过官方提供的安装方式获取 T3 Code（参考官网最新指引，通常为 npm 全局安装或下载桌面客户端）。首次启动后按引导完成初始化，设置好工作区根目录。建议单独建一个空目录作为实验工作区，避免污染现有项目。
💡 小贴士：安装前先运行 node -v 确认版本，低于 18 会直接报错。
2

第2步：提前装好并登录各个 Agent

T3 Code 不自带 Agent，所以要先在系统里装好 Claude Code 并完成登录鉴权，确认在普通终端里能正常对话。如果还想接入 Codex 或 Cursor，也分别安装并登录。每个 Agent 都要先在 T3 Code 之外跑通一次，排除环境问题。
💡 小贴士：逐个验证：在系统终端里分别运行 claude 和 codex，能正常响应再进下一步。
3

第3步：在 T3 Code 中注册 Agent 并配置启动命令

打开 T3 Code 的 Agent 管理面板，新增 Agent 条目，填入名称、启动命令（如 claude 或 codex）和工作目录。为每个 Agent 设置不同的标识色和快捷键，方便在控制台里快速区分。保存后逐个点击测试，确认能在 T3 Code 内拉起对应 Agent 会话。
💡 小贴士：启动命令里可以带上常用参数（如指定模型），省去每次手动输入。
4

第4步：建立多 Agent 任务面板与并行会话

在工作区中为每个 Agent 创建独立会话标签，把同一个需求分别发给 Claude Code 和 Codex，观察两者输出差异。利用 T3 Code 的分屏或标签切换能力，让多个 Agent 并行跑不同子任务（如一个写测试、一个改实现）。为每个会话命名，例如「重构-登录模块」「测试-支付流程」，保持任务边界清晰。
💡 小贴士：并行任务尽量拆到不同文件或模块，避免多个 Agent 同时改同一文件产生冲突。
5

第5步：用 Git 做改动对比与回滚

在每个 Agent 完成任务后，用 git diff 查看具体改动，对比不同 Agent 的方案质量。选定满意版本后提交，不满意则 git checkout 回滚。建议每轮 Agent 操作前先 commit 一次基线，形成「基线-实验-对比-采纳」的闭环。
💡 小贴士：给每个 Agent 的产出单独建分支，对比时用 git diff branchA branchB 一目了然。
6

第6步：沉淀常用 Prompt 模板与工作流

把反复使用的任务描述整理成 Prompt 模板，存放在工作区的 prompts 目录中，每次直接粘贴给对应 Agent。针对固定流程（如「先让 Claude 出方案，再让 Codex 实现」）写成简单的操作清单，形成可复用的多 Agent 工作流。定期清理失效会话，保持控制台整洁。
💡 小贴士：模板里预留 {文件路径}、{需求描述} 占位符，替换起来更快。

✨ 完成后你会得到

打开 T3 Code 后能看到多个 Agent 会话并列在同一控制台，每个会话有清晰命名和独立工作目录；你可以同时向 Claude Code 和 Codex 下发任务，通过 Git diff 对比两者产出并择优采纳，整个多 Agent 协作流程在一个界面内闭环完成。

❓ 常见问题

T3 Code 需要付费吗？ ▼
T3 Code 本身是控制台工具，具体收费以其官网为准；它不包含模型额度，各 Agent 的 API 费用仍需按 Claude、OpenAI 等官方计费。
没有 Claude Code 能用 T3 Code 吗？ ▼
可以，T3 Code 不绑定特定 Agent，只要你能在终端里跑通的 Agent CLI 基本都能接入，但教程以 Claude Code 为主线。
多个 Agent 同时改代码会冲突吗？ ▼
会。建议按文件或模块拆分任务，或让每个 Agent 在独立分支上工作，最后用 Git 合并对比。
T3 Code 和直接开多个终端有什么区别？ ▼
T3 Code 提供统一的会话管理、命名、分屏和状态视图，Agent 多了以后比裸终端清晰得多，减少上下文切换成本。
Windows 上能用吗？ ▼
多数 Agent CLI 和 T3 Code 支持 Windows，但部分工具对 WSL 更友好，建议优先在 WSL 或 macOS/Linux 下操作。

🚀 进阶玩法

  • 🔹 变体1：双 Agent 交叉评审——让 Claude Code 写实现、Codex 做 Code Review，再把评审意见回灌给 Claude 修改，形成自动互审闭环。
  • 🔹 变体2：任务流水线——用 T3 Code 按「需求分析 → 方案设计 → 编码实现 → 测试生成」拆成四个会话，分别指派不同 Agent，人工在节点间把关。
  • 🔹 变体3：模型对比实验——同一 Prompt 同时发给 3 个 Agent，用 Git 分支保存各自产出，定期统计采纳率来挑选主力 Agent。

💡 一句话总结

T3 Code 的精髓不是替你写代码，而是把多个 Agent 变成可调度、可对比、可回滚的「团队成员」，让多 Agent 协作从混乱走向可控。
