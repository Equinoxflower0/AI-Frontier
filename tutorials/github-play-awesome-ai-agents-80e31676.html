第1步：克隆仓库并建立本地索引

💡 小贴士：如果仓库很大，可以用 ripgrep 命令 rg -i "pattern" 快速定位，比 VS Code 搜索更快。
2

第2步：筛选 3 个与你场景最匹配的模式

根据你当前的项目需求，从目录中挑出 3 个模式。比如做客服机器人，可以选「ReAct」「Tool Use」「Memory」；做自动化报告，可以选「Plan-and-Execute」「Reflection」「Multi-Agent」。把每个模式的说明、适用场景、示例代码复制到一个单独的 Markdown 文件里，方便对比。
💡 小贴士：不要贪多，先选 3 个，跑通一个再扩展。模式之间往往可以组合，但一开始要控制复杂度。

第3步：把模式转成可运行的提示词或工具链

针对每个模式，写一个最小可运行示例。例如 ReAct 模式，可以用 LangChain 的 create_react_agent，配一个搜索工具和计算工具。把模式文档里的伪代码或描述翻译成你熟悉的框架代码。运行后观察输出是否符合预期，如果不符合，回到模式文档检查是否漏了关键约束。
💡 小贴士：建议用 Jupyter Notebook 逐步调试，每一步都打印中间结果，方便定位问题。
4

第4步：组合多个模式搭建完整工作流

把第 3 步跑通的模式串起来。比如先用「Plan-and-Execute」做任务拆解，再用「Tool Use」调用外部 API，最后用「Reflection」做结果校验。用 LangGraph 或自己写一个简单的状态机来管理流程。每加一个模式，就回归测试一次，确保整体稳定。
💡 小贴士：组合时注意模式之间的输入输出格式要统一，建议先定义好一个中间数据结构（如 JSON Schema）。

第5步：记录效果并回馈社区

把你的实现过程、踩坑记录、效果对比写成一篇笔记或博客。如果发现某个模式有改进空间，可以在原仓库提 Issue 或 PR。也可以把你的组合方案整理成一个新的模式，提交给 awesome-agentic-patterns，帮助更多人。

❓ 常见问题

这个仓库和 LangChain 有什么区别？ ▼
仓库是模式目录，偏设计思路和最佳实践；LangChain 是代码框架，偏实现。两者互补，先用仓库选模式，再用 LangChain 落地。
没有编程基础能玩吗？ ▼
可以，但只能读懂模式描述和提示词模板。要跑通工具链和工作流，至少需要会 Python 或 JavaScript 基础。
模式太多，怎么选？ ▼
先明确你的任务类型：是单轮问答、多轮对话、还是自动化流程？然后按仓库里的分类标签筛选，优先选有示例代码的模式。
需要付费 API 吗？ ▼
大部分模式可以用本地模型（如 Ollama）跑，但效果可能不如 GPT-4 或 Claude。建议先用免费额度测试，再决定是否付费。
如何判断一个模式是否适合我？ ▼
看三点：输入输出是否匹配你的场景、依赖工具你是否具备、复杂度是否在你能维护的范围内。先跑最小示例，再决定是否深入。

🚀 进阶玩法

  • 🔹 变体1：只取「提示词模板」类模式，做成一个 Prompt 库，配合 ChatGPT 或 Claude 直接使用，适合非开发者。
