🎯 为什么值得玩

传统 RAG 需要写 Python 代码串联向量库、检索器和 LLM，对数据工程师不够友好。这个玩法利用 SQL 的 STORED 生成列自动完成文本向量化，再用 SQL 函数调用 MaaS 大模型做推理和 RAG，把分类、概括、依据资料回答都变成可保存的文本结果。它特别适合已有关系型数据库、想低成本引入 AI 能力的团队，比如智能客服知识库、工单自动分类、文档问答等场景。

📝 一步步教你做

1

第1步：准备数据库与向量扩展

在 PostgreSQL 中执行 CREATE EXTENSION IF NOT EXISTS vector; 启用 pgvector。然后创建一张文档表，包含 id、content 原文列和 embedding 向量列，其中 embedding 定义为 GENERATED ALWAYS AS (llm_embed(content)) STORED，让原文写入时自动计算向量。最后为 embedding 列建立 ivfflat 或 hnsw 索引加速语义检索。
💡 小贴士：生成列表达式里调用的 llm_embed 需要提前用 PL/Python 或外部函数封装好，确保写入时能同步调用向量化 API。
2

第2步：封装 SQL 函数调用大模型

用 PL/Python 或 LlamaIndex 的 SQL 工具链，创建 llm_embed(text) 和 llm_infer(prompt) 两个 SQL 函数，分别对接 MaaS 的向量化接口和推理接口。llm_infer 接收提示词模板并返回文本结果，方便在 SELECT 中直接调用。注意在函数内处理 API Key 和超时重试。
💡 小贴士：把 API Key 放在数据库的 vault 或环境变量里，不要硬编码在 SQL 函数中。
3

第3步：写入文档并自动向量化

向文档表 INSERT 原文内容，embedding 列会由 STORED 生成列自动计算并保存，原文与向量同表。可以用 INSERT INTO docs(content) VALUES ('...') 批量导入知识库文档。写入后查询 SELECT id, content, embedding IS NOT NULL FROM docs 确认向量已生成。
💡 小贴士：批量写入时建议分批提交，避免单次事务调用太多次向量化 API 导致超时。
4

第4步：用 SQL 做语义检索与 RAG 组料

对用户问题先用 llm_embed 得到查询向量，再用 ORDER BY embedding <-> query_vec LIMIT 5 取回候选原文。把候选原文拼接成上下文，套入提示词模板，调用 llm_infer 生成最终回答。整个 RAG 流程可以写成一条 CTE 或视图，例如 WITH candidates AS (...) SELECT llm_infer('根据资料回答：' || question || ' 资料：' || string_agg(content, ' ')) FROM candidates。
💡 小贴士：候选数量 3-5 条通常够用，太多会稀释关键信息并增加 token 成本。
5

第5步：用 LlamaIndex 串联并一键试用

在 Python 中用 LlamaIndex 的 SQL 查询引擎或自定义 Tool 包装上述 SQL 函数，把“检索+推理”暴露成一个自然语言接口。也可以直接写一个 runnable demo：输入问题，执行 SQL，打印回答和引用原文。最后用几条测试问题验证分类、概括和依据资料回答三种能力。
💡 小贴士：把 SQL 查询结果和引用来源一起返回，方便排查 RAG 回答是否忠实于资料。

✨ 完成后你会得到

完成上述步骤后，你可以在数据库里直接执行 SQL 完成文本分类、概括和基于知识库的问答，回答结果可返回也可保存到表中；原文与向量同表存储，语义检索通过向量距离排序快速取回候选资料，整个 RAG 流程无需离开 SQL 环境。

❓ 常见问题

没有 PostgreSQL 可以用 MySQL 吗？ ▼
MySQL 8.0 支持生成列但不原生支持向量类型和距离运算，需要借助外部向量库或改用 PostgreSQL + pgvector 方案。
生成列里调用外部 API 会不会很慢？ ▼
写入时会同步调用向量化 API，批量导入建议分批并开启并发；查询时只调用一次 llm_embed 得到查询向量，影响可控。
如何保证 RAG 回答不胡编？ ▼
在提示词中明确要求“仅根据资料回答，资料没有就说不知道”，并返回引用原文供人工核对。
API Key 放在 SQL 函数里安全吗？ ▼
不建议硬编码，使用数据库 vault、环境变量或密钥管理服务，并限制函数执行权限。
这个方案适合多大数据量？ ▼
pgvector 的 hnsw 索引可支撑百万级向量，更大规模建议分表或引入专用向量数据库。

🚀 进阶玩法

  • 🔹 变体1：把 llm_infer 换成分类专用提示词，用 SQL 批量给工单打标签并写回标签列。
  • 🔹 变体2：用定时任务对新增文档自动生成摘要列，实现知识库自动摘要与去重。
  • 🔹 变体3：结合 LlamaIndex 的 Agent 把 SQL 函数注册为工具，让模型自主决定何时检索、何时推理。
