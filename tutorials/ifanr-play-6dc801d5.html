第1步：获取 DeepSeek API Key

登录 DeepSeek 开放平台，进入「API Keys」页面，点击「创建 API Key」，复制生成的密钥并妥善保存。注意：密钥只显示一次，丢失需重新创建。建议将密钥设置为环境变量，避免硬编码在代码中。
💡 小贴士：免费额度有限，可先充值少量金额测试；密钥不要泄露到公开仓库。
2

第2步：安装依赖并初始化客户端

在终端执行 pip install openai 安装官方 SDK。然后新建 Python 文件，导入 OpenAI 类，用 api_key 和 base_url='https://api.deepseek.com' 初始化客户端。这样就能像调用 OpenAI 一样调用 DeepSeek 模型。
💡 小贴士：base_url 必须带 https://，且不要加 /v1 后缀（DeepSeek 兼容路径已内置）。
3

第3步：设计历史记录存储结构

创建一个列表 messages 来保存对话历史，每条消息为 {'role': 'user'/'assistant', 'content': '文本'} 格式。每次用户输入后，将用户消息追加到列表，再调用 API 时把整个列表作为 messages 参数传入。这样模型就能看到完整上下文。
💡 小贴士：可以定期将 messages 保存到 JSON 文件，实现跨会话持久化。
4

第4步：编写循环对话脚本

用 while True 循环接收用户输入，将输入追加到 messages，调用 client.chat.completions.create(model='deepseek-chat', messages=messages)，获取回复后追加到 messages 并打印。设置退出命令（如输入 'exit'）结束循环。
💡 小贴士：每次调用后检查返回的 usage 字段，监控 token 消耗，避免意外超支。
5

第5步：导入历史记录并测试不限额对话

准备一个历史对话的 JSON 文件（格式与 messages 一致），在脚本启动时加载到 messages 列表。运行脚本，连续提问多个问题，观察模型是否能引用之前的对话内容。由于 API 按 token 计费，理论上只要余额充足，对话轮次无硬性限制。
💡 小贴士：如果历史记录过长，可手动截断最早的消息，或使用摘要技术压缩上下文。

❓ 常见问题

DeepSeek API 真的不限额吗？ ▼
API 本身没有硬性轮次限制，但按 token 计费，余额耗尽则无法继续。只要账户有余额，就可以无限轮次对话。
历史记录太长导致 token 超限怎么办？ ▼
DeepSeek 模型有上下文窗口限制（如 64K），超出会报错。可以截断最早的消息，或使用摘要模型压缩历史，只保留关键信息。
可以用其他模型吗？ ▼
可以，DeepSeek API 兼容 OpenAI 格式，只需修改 model 参数为 'deepseek-chat' 或 'deepseek-reasoner'，也可替换 base_url 使用其他兼容服务。
如何保证 API Key 安全？ ▼
将密钥存储在环境变量中，代码里用 os.getenv 读取；不要将密钥提交到 Git 仓库；定期轮换密钥。
对话历史如何跨设备同步？ ▼
将 messages 列表保存到云存储（如数据库、对象存储），或使用网盘同步 JSON 文件，即可在多设备间共享历史。
