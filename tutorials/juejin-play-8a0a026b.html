🎯 为什么值得玩

MCP（Model Context Protocol）是让 AI 模型安全调用外部工具的标准协议。很多开发者第一次接触 MCP 时，会困惑于 Client 和 Server 的角色分工。本文基于掘金实战教程，带你从理解概念到动手实现一个能调用真实 HTTP 接口的 MCP Server，让你的 AI 助手不再局限于本地文件，而是能查询天气、获取新闻、调用任意 API。这个玩法适用于需要扩展 AI 能力边界、构建自定义工具链的场景。

📝 一步步教你做

1

第1步：理解 MCP Server 的角色与通信机制

MCP Server 是一个独立进程，通过标准输入输出（stdio）或 SSE 与 MCP Client（如 Copilot）通信。Server 向 Client 暴露一组“工具”（tools），每个工具定义名称、描述和参数 schema。Client 根据用户请求决定调用哪个工具，并将参数传给 Server，Server 执行实际逻辑（如 HTTP 请求）后返回结果。先阅读官方文档中关于 tools 的部分，明确 request/response 的 JSON-RPC 格式。
💡 小贴士：可以用官方提供的 @modelcontextprotocol/inspector 工具可视化调试 MCP Server，避免盲目猜测通信内容。
2

第2步：初始化项目并安装 MCP SDK

创建一个新的 Node.js 项目：mkdir mcp-http-server && cd mcp-http-server && npm init -y。然后安装依赖：npm install @modelcontextprotocol/sdk zod。zod 用于定义工具参数的 schema，SDK 会自动生成 JSON Schema 给 Client。在 package.json 中设置 "type": "module" 以使用 ES 模块。
💡 小贴士：建议使用 TypeScript 获得更好的类型提示，但纯 JavaScript 也能快速跑通。
3

第3步：编写 MCP Server 主文件，定义工具与 HTTP 调用逻辑

创建 server.js，导入 McpServer 和 StdioServerTransport。使用 server.tool() 方法注册一个工具，例如 get_weather，参数为城市名（zod schema）。在工具的处理函数中，使用 fetch 调用 Open-Meteo 的 API（如 https://api.open-meteo.com/v1/forecast?latitude=...&longitude=...&current_weather=true），将返回的 JSON 整理成文本返回。最后通过 StdioServerTransport 连接并启动服务器。
💡 小贴士：在工具描述中写清楚用途和参数格式，这直接影响 AI 选择工具的准确率。
4

第4步：在 VS Code 中配置 MCP Client 并测试

在 VS Code 的设置中（或项目 .vscode/mcp.json）添加 MCP Server 配置，指定 command 为 node，args 为 server.js 的绝对路径。重启 Copilot 或使用 MCP: List Servers 命令确认服务器已连接。然后在 Copilot Chat 中提问“北京今天天气怎么样？”，观察 Copilot 是否自动调用 get_weather 工具并返回结果。
💡 小贴士：如果工具未被调用，检查 Server 是否正常启动，以及工具描述是否足够清晰。
5

第5步：扩展更多 HTTP 工具并处理错误

仿照 get_weather，再添加一个 get_random_quote 工具，调用 https://api.quotable.io/random。在工具处理函数中加入 try-catch，对 HTTP 错误状态码返回友好的错误信息，避免整个 Server 崩溃。同时可以使用 zod 对参数进行校验，比如城市名不能为空。
💡 小贴士：为每个工具设置合理的超时时间（如 5 秒），防止慢接口阻塞 AI 响应。

✨ 完成后你会得到

Copilot 能识别并调用你自定义的 MCP 工具，当用户询问天气或名言时，AI 会自动发起 HTTP 请求并将真实数据整合到回答中。你可以在 VS Code 的输出面板看到 MCP Server 的日志，确认工具被调用和返回结果。

❓ 常见问题

MCP Server 和普通 HTTP 服务器有什么区别？ ▼
MCP Server 使用 JSON-RPC 协议通过 stdio 或 SSE 与 Client 通信，专门为 AI 工具调用设计；普通 HTTP 服务器使用 REST 等协议，需要额外适配层。
为什么 Copilot 没有调用我的工具？ ▼
常见原因：Server 未启动、工具描述不清晰、参数 schema 错误。建议用 MCP Inspector 手动测试工具是否可用，并优化工具描述。
可以在 MCP Server 中调用需要认证的 API 吗？ ▼
可以。将 API Key 放在环境变量中，在 Server 启动时读取，并在 HTTP 请求头中携带。注意不要将密钥硬编码在代码里。
MCP Server 只能用于 Copilot 吗？ ▼
不是。任何支持 MCP 协议的 Client 都可以连接，如 Claude Desktop、Cursor 等。只要配置正确的启动命令即可。

🚀 进阶玩法

  • 🔹 变体1：将 HTTP 调用替换为数据库查询，开发一个 MCP Server 让 AI 能直接查询 SQLite 或 PostgreSQL 中的数据。
  • 🔹 变体2：组合多个工具形成工作流，例如先调用 get_weather 再调用 get_air_quality，让 AI 综合多个 API 结果给出建议。
  • 🔹 变体3：使用 SSE 传输替代 stdio，将 MCP Server 部署为远程服务，供多个 Client 共享。
