📝 一步步教你做

1

第1步：克隆并浏览 awesome-opencode 清单

打开终端，执行 git clone https://github.com/awesome-opencode/awesome-opencode.git，然后进入目录用编辑器打开 README.md。清单按插件、主题、智能体、项目等分类，每个条目附带简短描述和链接。先快速扫一遍分类标题，了解有哪些资源类型。
💡 小贴士：用 VS Code 的 Markdown 预览功能（Ctrl+Shift+V）可以更直观地浏览清单结构。
2

第2步：筛选并记录目标插件与智能体

根据你的需求（比如代码补全、Git 集成、UI 主题），在清单中挑选 2-3 个插件和 1-2 个智能体。把它们的名称、仓库链接和安装说明复制到一个临时笔记中。注意查看每个条目的标签（如 official、community），优先选择维护活跃的项目。
💡 小贴士：在 GitHub 上查看仓库的最近提交时间和 issue 活跃度，避免选用已废弃的插件。
3

第3步：安装 OpenCode 并配置基础环境

按照 OpenCode 官网指引安装 CLI（如 npm install -g opencode 或下载二进制）。运行 opencode --version 确认安装成功。然后在项目根目录创建 opencode.json 配置文件，填入你的 API 密钥和基础模型设置。
💡 小贴士：如果使用本地模型，可以在配置中指定 baseURL 指向 Ollama 或 LM Studio 的本地端口。
4

第4步：安装并启用选定的插件

根据第2步记录的插件安装说明，通常通过 npm 安装或直接在 opencode.json 的 plugins 数组中添加插件包名。例如添加 "plugins": ["opencode-plugin-git"]。保存配置后重启 OpenCode，用 /plugins 命令（或查看日志）确认插件已加载。
💡 小贴士：一次只加一个插件，测试通过后再加下一个，方便定位冲突。

第5步：导入智能体并测试工作流

在清单中找到智能体条目，通常是一个 Markdown 或 JSON 文件。将其复制到项目的 .opencode/agents/ 目录（或配置中指定的路径）。在 OpenCode 对话中用 @agent-name 调用该智能体，输入一个简单任务（如“审查当前文件的代码风格”）验证是否生效。
💡 小贴士：智能体的提示词文件可以自行微调，加入你团队的编码规范效果更好。
6

第6步：应用主题并固化配置

从清单的主题分类中选一个喜欢的主题，按说明安装（通常是复制 CSS 或修改配置中的 theme 字段）。重启后检查界面变化。最后把 opencode.json 和 .opencode/ 目录提交到 Git，方便团队共享。
💡 小贴士：主题文件一般很小，可以直接放进仓库；插件依赖建议在 README 中注明安装命令。

❓ 常见问题

awesome-opencode 清单里的插件都兼容最新版 OpenCode 吗？ ▼
不一定。清单是社区维护的，部分插件可能滞后。安装前查看插件仓库的 package.json 中 peerDependencies 或 README 的兼容说明，优先选最近 3 个月有更新的项目。
安装插件后 OpenCode 启动报错怎么办？ ▼
先移除最近添加的插件，确认基础功能正常。然后查看 OpenCode 日志（通常用 --verbose 启动）定位缺失的依赖或版本冲突。也可以到插件仓库的 issue 区搜索类似错误。
智能体和插件有什么区别？ ▼
插件是扩展 OpenCode 功能的代码模块（如新增命令、工具集成）；智能体是预配置的提示词角色（如“代码审查员”），通过 @ 调用，不涉及代码安装。两者可以组合使用。
可以同时使用多个主题吗？ ▼
通常只能激活一个主题。你可以在配置中快速切换，但不要同时加载多个主题文件，否则样式会冲突。
如何向 awesome-opencode 清单贡献自己的插件？ ▼
Fork 仓库，按照 README 中的贡献指南在对应分类下添加条目，附上简短描述和链接，然后提交 Pull Request。维护者审核后会合并。
