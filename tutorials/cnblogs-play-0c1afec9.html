🎯 为什么值得玩

很多开发者面对一堆插件源码时，容易陷入逐行读代码的低效循环。这个玩法把「读源码」变成「写报告」：先锁定七个插件仓库和 Git 工作树证据基线，再让 AI 按统一模板产出七份分项报告，最后汇总成横向对比和可视化图表。它适合技术调研、插件选型、团队内部分享，也适合作为 AI 辅助代码分析的实战练习。整个过程不修改源码、不引入耦合，产出的是可复用的分析文档。

  • Git → 访问
    克隆并管理工作树，获取 package.json 等证据基线
  • VS Code → 访问
    浏览七个插件仓库源码，配合 AI 插件做局部提问
  • ChatGPT / Claude / DeepSeek → 访问
    按模板生成七份分项报告和横向对比
  • Markdown 编辑器（Typora / Obsidian） → 访问
    整理报告、图表和最终汇总文档
  • Mermaid Live Editor → 访问
    把报告中的架构关系转成 10 张可视化图表

📝 一步步教你做

1

第1步：锁定七个插件仓库与证据基线

在 D:\self\code\cj 下确认七个 DSH 插件源码仓库，逐个执行 git status 和 git log -1 记录工作树状态。打开每个仓库的 package.json，摘出 name、version、main、dependencies、scripts 五个字段作为统一证据基线。把七个仓库的路径和基线信息整理成一张清单表，后续每份报告都引用这张表，保证分析口径一致。
💡 小贴士：先不要读业务代码，只收集元信息，避免一开始就被细节带偏。
2

第2步：设计七份分项报告的统一模板

为每个插件定义固定四段式：实现原理（入口文件、核心模块、数据流）、插件效果（对外暴露的 API 或 UI 行为）、优缺点（各列 3 条）、横向对比（与其余六个插件的差异点）。再追加「证据引用」小节，要求每条结论标注来源文件路径和行号区间。把模板存成 report-template.md，七份报告都从它复制。
💡 小贴士：模板里强制写「证据引用」，能显著降低 AI 编造结论的概率。
3

第3步：逐仓库投喂 AI 生成七份报告

对每个仓库，把 package.json、入口文件、核心目录树和关键源码片段按模板顺序粘贴给 AI，并附上第 1 步的基线清单作为上下文。要求 AI 严格按四段式输出，每条结论后带文件路径和行号。生成后人工抽查「实现原理」段是否与入口文件一致，不一致就补充源码片段重跑。七份报告分别存为 report-01.md 到 report-07.md。
💡 小贴士：单次投喂控制在 3-5 个文件，太多会稀释 AI 对关键模块的注意力。
4

第4步：汇总横向对比与十张可视化图表

把七份报告一起交给 AI，要求输出一张七行四列的对比矩阵（插件名 × 原理/效果/优点/缺点），并提炼「七层表面上的七种插件形态」这一主线。然后用 Mermaid 语法生成 10 张图：1 张总览架构图、7 张单插件模块图、2 张横向对比图。把 Mermaid 代码贴到 Mermaid Live Editor 渲染并导出 SVG。
💡 小贴士：对比矩阵先让 AI 用 Markdown 表格输出，再转 Mermaid，返工成本更低。
5

第5步：交叉校验并产出最终拆解文档

逐条核对七份报告中的证据引用是否真实存在，删掉无法定位的结论。检查横向对比矩阵中每个插件是否都被其余六个插件覆盖到，补齐缺失的对比格。最后把七份报告、对比矩阵和 10 张图合并成一份总文档，开头写「0 处源码级耦合」的分析边界说明，结尾附七个仓库的 Git 工作树快照链接。
💡 小贴士：校验阶段优先看「优缺点」段，这里最容易出现没有证据支撑的主观判断。

❓ 常见问题

七个仓库必须全部读完源码吗？ ▼
不需要。每份报告只聚焦入口文件、核心模块和 package.json，其余代码按需片段引用，重点是证据可追溯而非覆盖全部行。
AI 生成的结论和源码对不上怎么办？ ▼
回到模板中的「证据引用」要求，让 AI 重新标注文件路径和行号；仍对不上就补充该文件片段重跑，不要直接采用无出处的结论。
10 张图表必须用 Mermaid 吗？ ▼
不是必须，但 Mermaid 是文本描述、易版本管理、易让 AI 生成，配合 Mermaid Live Editor 可以快速渲染和导出。
这个玩法能用于非 DSH 的插件项目吗？ ▼
可以。把「七个仓库」替换成任意插件集合，保留四段式模板和证据引用机制即可复用。
分析边界里的「0 处源码级耦合」是什么意思？ ▼
指分析过程只读不写，报告与源码之间没有代码级依赖，删掉报告不影响插件运行，方便随时重跑或替换分析对象。

🚀 进阶玩法

  • 🔹 变体1：把七份报告改成「七问七答」访谈体，每个插件用 7 个固定问题驱动 AI 回答，适合做团队分享稿。
  • 🔹 变体2：只选三个插件做深度版，每份报告增加调用时序图和性能开销估算，适合插件选型决策。
  • 🔹 变体3：把报告模板固化成 prompt 模板文件，配合脚本批量投喂七个仓库，适合仓库数量更多的场景。

💡 一句话总结

用统一模板加证据引用，把读源码变成写报告，七份报告加十张图就能零耦合拆解整个插件生态。
