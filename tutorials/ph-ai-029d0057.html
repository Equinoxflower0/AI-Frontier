🎯 为什么值得玩

MCP（Model Context Protocol）虽然流行，但存在权限过大、缺乏细粒度审计等安全隐患。UTCP（Universal Tool Calling Protocol）由 Ruby 社区推出，主打“安全替代 MCP”，通过声明式工具定义和沙箱执行，让 AI 只能调用你明确授权的函数。它适合需要让 AI 操作数据库、文件系统或内部 API，但又不想开放全盘权限的开发者。本教程基于 Product Hunt 上的 Ruby UTCP 项目，带你完成一次最小可用的工具调用。

📝 一步步教你做

1

第1步：初始化 Ruby 项目并安装 UTCP

在终端执行 `mkdir utcp-demo && cd utcp-demo && bundle init`，然后编辑 Gemfile 加入 `gem 'utcp'`，运行 `bundle install`。接着创建 `server.rb` 和 `client.rb` 两个文件。确保 Ruby 版本不低于 3.2，否则部分语法会报错。
💡 小贴士：如果 gem 安装慢，可以换国内源：`bundle config mirror.https://rubygems.org https://gems.ruby-china.com`。
2

第2步：用 UTCP 声明一个安全工具（只读文件）

在 `server.rb` 中引入 UTCP，定义一个名为 `read_safe_file` 的工具，限制只能读取 `/tmp/utcp-demo/` 目录下的文件。使用 `UTCP::Tool.define` 指定参数 schema（如 `path` 字符串），并在执行块中校验路径前缀。这样即使 AI 请求 `/etc/passwd` 也会被拒绝。
💡 小贴士：工具描述里写清楚“仅允许读取 /tmp/utcp-demo/ 下的文件”，LLM 会更少乱试。
3

第3步：启动 UTCP 服务端并注册工具

在 `server.rb` 末尾调用 `UTCP::Server.start(port: 4567)`，并注册刚才的工具。运行 `ruby server.rb`，看到 `UTCP server listening on 4567` 即成功。服务端会自动生成一个工具清单 JSON，可通过 `curl http://localhost:4567/tools` 查看。
💡 小贴士：生产环境建议加上 `--auth-token` 参数，UTCP 支持简单 Bearer Token 验证。
4

第4步：编写客户端，让 LLM 生成工具调用

在 `client.rb` 中先获取工具清单，然后把清单和用户问题（例如“读取 /tmp/utcp-demo/hello.txt 的内容”）一起发给 LLM。LLM 会返回一个 JSON 格式的工具调用请求，例如 `{"tool":"read_safe_file","args":{"path":"/tmp/utcp-demo/hello.txt"}}`。客户端解析后通过 UTCP 的 `call_tool` 方法发送到服务端。
💡 小贴士：如果不想接真实 LLM，可以手动构造这个 JSON 来测试，效果一样。
5

第5步：执行调用并验证安全拦截

服务端收到请求后，UTCP 会先校验参数 schema，再执行工具块。对于合法路径，返回文件内容；对于非法路径（如 `/etc/passwd`），返回 `Permission denied` 错误。客户端把结果回传给 LLM 或直接打印。你可以在 `server.rb` 里加日志，观察每次调用的参数和结果。
💡 小贴士：用 `tail -f` 看服务端日志，能清楚看到哪些请求被拦截，方便调试。

✨ 完成后你会得到

你得到一个可运行的 UTCP 工具链：LLM 能安全地请求读取指定目录下的文件，非法路径被自动拒绝。终端会显示工具调用日志和返回内容，证明 UTCP 的权限控制生效。

❓ 常见问题

UTCP 和 MCP 到底有什么区别？ ▼
MCP 通常把整个工具集暴露给 AI，权限较粗；UTCP 强调每个工具独立声明、沙箱执行和细粒度路径/参数校验，更适合安全敏感场景。
必须用 Ruby 吗？ ▼
目前官方实现是 Ruby，但协议本身是语言无关的，社区已有 Python/Node 的试验性客户端。
没有 LLM API 能玩吗？ ▼
可以，手动构造工具调用 JSON 发给 UTCP 服务端即可，教程第4步的 tip 有说明。
UTCP 支持流式输出吗？ ▼
当前版本主要支持请求-响应模式，流式工具调用在路线图中，可关注 Product Hunt 页面更新。
如何添加更多工具？ ▼
在 server.rb 里继续用 `UTCP::Tool.define` 定义新工具并注册，客户端会自动从 `/tools` 获取最新清单。

🚀 进阶玩法

  • 🔹 变体1：把工具换成“查询 SQLite 数据库”，限制只能执行 SELECT 语句，防止 AI 删表。
  • 🔹 变体2：用 UTCP 包装一个内部 HTTP API，让 AI 只能调用白名单内的端点，并自动记录审计日志。
  • 🔹 变体3：结合 Ollama 本地模型，完全离线运行 UTCP 工具链，适合隐私要求高的环境。
