🎯 为什么值得玩

很多开发者把 PDF 直接丢进 RAG 系统后，检索出来的片段全是断句的表格、错位的标题，大模型拿着碎片化内容一本正经地编答案。你以为是 Embedding 模型不行、切片大小不对、向量库检索策略有问题，折腾一圈才发现根源在 PDF 解析环节。Docling 是 IBM 开源的文档解析工具，能精准识别表格、标题、列表等结构，输出干净的 Markdown，再配合 LlamaIndex 的 Markdown 解析器，就能让 RAG 系统拿到高质量的上下文。这个玩法适合所有需要处理 PDF 文档的知识库、问答系统、文档分析场景。

📝 一步步教你做

1

第1步：安装依赖并验证 Docling 环境

创建虚拟环境后执行 pip install docling llama-index llama-index-readers-file。Docling 依赖较重，首次安装会下载布局模型和表格识别模型，耐心等待。安装完成后运行 python -c "from docling.document_converter import DocumentConverter" 确认无报错。
💡 小贴士：如果网络慢，可以设置 HF_ENDPOINT=https://hf-mirror.com 加速模型下载。
2

第2步：用 Docling 把 PDF 转成结构化 Markdown

写一个 convert.py，用 DocumentConverter().convert("test.pdf") 得到 docling_doc，再调用 docling_doc.document.export_to_markdown() 保存为 test.md。打开生成的 Markdown 检查表格是否保留为管道表格、标题层级是否用 # 正确标记。这一步是整个链路的质量基石，务必人工抽检几页。
💡 小贴士：Docling 默认开启表格结构识别，如果表格复杂可加参数 do_table_structure=True 并调高图像分辨率。
3

第3步：用 LlamaIndex 加载 Markdown 并构建索引

在 build_index.py 中用 SimpleDirectoryReader 读取上一步的 test.md，然后 SentenceSplitter(chunk_size=512, chunk_overlap=50) 做切片。接着 VectorStoreIndex.from_documents(documents, embed_model=OpenAIEmbedding()) 构建向量索引，并 persist 到本地 ./storage 目录。
💡 小贴士：Markdown 的标题会被 LlamaIndex 识别为元数据，检索时可以按标题过滤，效果更好。
4

第4步：搭建查询引擎并测试检索质量

加载持久化的索引，用 index.as_query_engine(similarity_top_k=3) 创建查询引擎。准备 5 个针对表格和标题的问题（例如“2023 年 Q4 营收是多少”），对比直接解析 PDF 的旧方案，观察回答是否准确引用表格数据。如果答案仍不理想，回头检查 Markdown 中对应片段是否完整。
💡 小贴士：打印 retrieved_nodes 的文本内容，确认检索到的片段没有断句或错位，这是排查 RAG 问题的关键。
5

第5步：批量处理 PDF 并接入完整 RAG 流程

把 convert.py 改造成遍历文件夹的批量脚本，将所有 PDF 转成 Markdown 后统一用 SimpleDirectoryReader 加载。再接入 OpenAI LLM 做生成，形成“PDF → Docling → Markdown → LlamaIndex 索引 → 查询”的完整链路。最后用 Gradio 或 FastAPI 包一层接口，方便日常使用。
💡 小贴士：批量转换时加个进度条和异常捕获，单个 PDF 失败不影响整体流程。

✨ 完成后你会得到

Docling 输出的 Markdown 中表格保持完整、标题层级清晰；LlamaIndex 检索到的片段语义连贯，大模型回答能准确引用表格数据和章节内容，不再出现断句拼接或胡编乱造。

❓ 常见问题

Docling 解析速度很慢怎么办？ ▼
首次运行会下载模型，之后会缓存。如果仍慢，可以关闭表格结构识别（do_table_structure=False）或降低图像分辨率，也可以改用 GPU 加速。
扫描版 PDF 能解析吗？ ▼
Docling 主要针对文本型 PDF，扫描版需要先做 OCR。可以先用 PaddleOCR 或 Tesseract 转成文本层，再交给 Docling 做结构化。
必须用 OpenAI 的 Embedding 吗？ ▼
不是，LlamaIndex 支持 HuggingFace、Ollama、Cohere 等多种 Embedding，替换 embed_model 即可，本地模型推荐 bge-m3。
Markdown 里的表格在切片时被切断了怎么办？ ▼
调大 chunk_size 或使用 LlamaIndex 的 MarkdownNodeParser，它会按标题层级切分，尽量保持表格完整。
这个方案和直接解析 PDF 相比提升有多大？ ▼
在表格密集和多级标题的文档上提升明显，检索准确率通常能提高 20%-40%，具体取决于文档复杂度和切片策略。

🚀 进阶玩法

  • 🔹 变体1：把 Docling 换成 Marker 或 Unstructured，对比不同解析器在表格和公式上的表现，选最适合自己文档类型的工具。
  • 🔹 变体2：在 LlamaIndex 中加入 MetadataExtractor，把 Docling 识别出的标题层级写入元数据，检索时按章节过滤，进一步提升精度。
  • 🔹 变体3：将 Docling 输出的 Markdown 同时喂给 GraphRAG，利用标题和表格关系构建知识图谱，适合需要跨文档推理的场景。

💡 一句话总结

RAG 效果差先别怪模型，用 Docling 把 PDF 解析成结构化 Markdown，再交给 LlamaIndex，才是高质量检索的正确打开方式。
