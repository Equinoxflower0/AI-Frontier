🎯 为什么值得玩

前端 API 迭代快，Agent 常凭训练数据写出已废弃或兼容性差的代码。Modern Web Guidance 把本地混合检索、特性门控和指南评测接入 Agent，让它在生成代码前按需查询浏览器能力，并给出兼容回退方案。适合需要稳定交付、多端兼容的前端项目，也适合想约束 Agent 输出质量的团队。

  • Claude Code / Cursor / 任意支持 MCP 的编码 Agent → 访问

📝 一步步教你做

1

第1步：克隆仓库并安装依赖

从掘金文章中找到 Modern Web Guidance 的仓库地址，执行 git clone 后进入目录运行 npm install。确认 package.json 中的 scripts 包含检索和评测命令。
💡 小贴士：先跑一次 npm run build 确认指南数据能正常生成，避免后续检索为空。
2

第2步：启动本地混合检索服务

运行仓库提供的检索服务命令（如 npm run serve 或 node server.js），默认监听本地端口。用 curl 测试一个查询，例如「dialog element」，确认返回相关指南片段。混合检索会结合关键词和向量相似度，比纯关键词更懂语义。
💡 小贴士：如果返回结果太少，检查指南数据是否已索引，或调大 topK 参数。
3

第3步：把检索能力接入编码 Agent

在 Agent 的 MCP 配置或自定义工具配置中，把本地检索服务注册为一个可调用工具，描述写成「查询浏览器 API 兼容性与用法」。在系统提示词里加一句：写浏览器相关代码前，先调用该工具查询目标 API。
💡 小贴士：提示词里明确要求「先查再写」，否则 Agent 容易跳过工具直接凭记忆生成。
4

第4步：用特性门控约束生成代码

在提示词模板中要求 Agent 对每个用到的浏览器特性做特性检测，例如 if ('showModal' in HTMLDialogElement.prototype)。让 Agent 在指南返回的兼容性信息基础上，自动生成回退分支，而不是直接假设 API 存在。
💡 小贴士：把「必须包含特性检测」写成硬性验收条件，方便后续评测。
5

第5步：跑指南评测并验收业务边界

用仓库自带的评测脚本对 Agent 生成的代码打分，检查是否引用了指南中的推荐用法、是否覆盖回退路径。再结合业务验收：原生弹窗等场景要确认焦点管理、ESC 关闭、无障碍属性是否满足产品要求。评测通过后再合入。
💡 小贴士：评测只保证「符合指南」，业务边界（如弹窗层级、动画时长）仍需人工验收。

✨ 完成后你会得到

Agent 在生成浏览器代码前会自动查询本地指南，输出带特性检测和兼容回退的代码；评测脚本给出通过报告，人工验收确认业务细节无误。

❓ 常见问题

没有 MCP 支持的 Agent 能用吗？ ▼
可以。把检索服务包装成 CLI 命令，在提示词里让 Agent 先执行命令再写代码，效果类似。
混合检索需要额外配置向量库吗？ ▼
仓库通常内置轻量索引方案，按 README 初始化即可；数据量大时再考虑外接向量库。
指南数据过时怎么办？ ▼
定期更新仓库并重建索引；也可在评测中加入 MDN 兼容性数据做交叉校验。
评测通过就代表代码能上线吗？ ▼
不代表。评测只验证指南符合度，业务验收、真机兼容和性能仍需人工把关。

🚀 进阶玩法

  • 🔹 变体1：把检索服务换成远程 API，让团队共用一份指南索引，Agent 配置里只填 URL。
  • 🔹 变体2：在 CI 中加一道指南评测门禁，Agent 生成的 PR 不通过评测就自动打回。
  • 🔹 变体3：针对特定框架（如 React/Vue）定制提示词模板，让回退方案直接生成对应框架写法。

💡 一句话总结

让 Agent 先查指南再写代码，用特性门控和评测把「凭记忆生成」变成「有据可查、可验收」。
