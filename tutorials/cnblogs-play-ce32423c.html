用上下文压缩机制排查 Agent 遗忘指令问题

🎯 为什么值得玩

很多开发者用 Agent 跑长流程任务时，都遇到过 Agent 中途「失忆」：明明说好「别动这个文件」，压缩完上下文它又去改了。这背后是 compaction（上下文压缩）机制在作祟——它把聊天记录总结成更短的版本以节省 token，但总结过程可能丢掉关键约束。本教程教你如何系统排查这类遗忘指令问题，适合使用 Claude Code、Cursor、Cline 等支持长上下文 Agent 的开发者。

  • Claude Code → 访问

  • Cursor → 访问
    备选 Agent IDE，可观察上下文压缩行为
  • Cline (VS Code 插件) → 访问
    开源 Agent 插件，可查看上下文管理日志
  • 一个长任务测试项目 → 访问
    准备一个包含多文件修改的仓库，用于触发 compaction
  • 文本对比工具 → 访问
    如 VS Code 内置 diff 或 Beyond Compare，用于对比压缩前后指令

📝 一步步教你做

1

第1步：复现遗忘场景并记录压缩触发点

在 Agent 中启动一个长任务，例如「重构项目中的 5 个文件，但不要修改 config.py」。持续对话直到出现「Compacting conversation…」提示。记录压缩前后的对话轮次和 Agent 行为变化，重点标记它开始违反约束的那一轮。
💡 小贴士：用屏幕录制或日志工具记录整个过程，方便回放定位。
2

第2步：提取压缩前后的上下文快照

在 Agent 工具中开启详细日志（如 Claude Code 的 --verbose 模式），找到 compaction 发生时的原始消息列表和压缩后的摘要。将两者导出为文本文件，用 diff 工具对比，找出被摘要丢弃的关键指令（如「别动 config.py」）。
💡 小贴士：关注摘要中是否把「不要做 X」这类否定约束弱化成了「注意 X」。
3

第3步：分析压缩策略并定位丢失原因

阅读你所用 Agent 的 compaction 实现文档或源码（如 Claude Code 的上下文管理逻辑），判断它是按轮次截断、按 token 预算摘要，还是用 LLM 重写。对照第2步的 diff 结果，确认是哪类信息被优先丢弃——通常否定指令和早期约束最容易被压缩掉。
💡 小贴士：如果工具闭源，可用多次实验归纳规律：改变指令位置和措辞，观察保留率。
4

第4步：设计抗压缩的指令加固方案

针对丢失的约束，采用三种加固方式：1）把关键约束写成系统提示或项目规则文件（如 CLAUDE.md），让压缩时优先保留；2）在每轮任务开始时用短句重申约束；3）把否定指令改为正向可执行清单（如「只修改 a.py、b.py」）。修改后重新跑同一长任务验证。
💡 小贴士：把约束放在对话最开头和最近一轮，两头夹击能显著降低丢失率。
5

第5步：验证修复效果并建立回归检查

重新执行原任务，观察 compaction 后 Agent 是否仍遵守约束。若仍遗忘，尝试调大上下文窗口或关闭自动压缩（如设置环境变量禁用 compaction）。最后把测试用例固化成脚本，每次升级 Agent 后跑一遍，防止回归。
💡 小贴士：在关键文件上设置只读权限，作为最后一道物理防线。

✨ 完成后你会得到

你能稳定复现 Agent 在 compaction 后遗忘指令的问题，并通过 diff 对比定位到被丢弃的约束；应用加固方案后，Agent 在长任务中遵守关键指令的成功率明显提升，且有一套可重复的回归测试流程。

❓ 常见问题

为什么 Agent 压缩后总是忘记「不要做某事」？ ▼
因为摘要模型倾向于保留正向任务描述，否定约束在压缩时容易被弱化或省略。把否定改为正向清单能缓解。
所有 Agent 的 compaction 机制都一样吗？ ▼
不一样。Claude Code、Cursor、Cline 的实现策略不同，有的按轮次截断，有的用 LLM 重写摘要。需要针对具体工具分析。
能否完全关闭上下文压缩？ ▼
部分工具支持（如环境变量或配置项），但关闭后可能因超长上下文导致报错或费用飙升。建议优先做指令加固而非直接关闭。
没有源码怎么分析压缩策略？ ▼
用控制变量法做黑盒实验：改变指令位置、措辞、长度，多次触发 compaction 并记录保留情况，归纳出规律。
这个排查方法适用于哪些场景？ ▼
适用于所有需要 Agent 执行多步骤长任务且包含关键约束的场景，如代码重构、批量文件处理、自动化运维等。

🚀 进阶玩法

  • 🔹 变体1：把关键约束写入项目根目录的规则文件（如 CLAUDE.md、.cursorrules），利用工具对规则文件的优先保留机制对抗压缩丢失。
  • 🔹 变体2：在每轮 Agent 回复后自动追加一条「约束提醒」消息，用脚本或钩子实现，确保最近上下文始终包含关键指令。
  • 🔹 变体3：对超长任务做分段拆解，每段任务结束后手动触发一次上下文重置并重新注入约束，避免单次压缩丢失过多信息。

💡 一句话总结

排查 Agent 遗忘指令的核心是：复现压缩、diff 快照、定位丢失、加固指令、回归验证——把「别动什么」变成「只动什么」，并让约束在上下文中两头夹击。
