用GradScaler排查混合精度训练NaN问题

混合精度训练中，GradScaler 是防止 fp16 梯度下溢的必备工具，但用不好反而会引入 NaN 问题。本教程教你用 GradScaler 的调试接口快速定位并修复 NaN，让模型训练不再“装死”。

🎯 为什么值得玩

fp16 的数值范围只有 6.1e-5 到 65504，远小于 fp32，梯度很容易下溢成 0 或上溢成 inf。下溢时模型静默失效，loss 不降但也不报错，排查起来非常痛苦。GradScaler 通过动态缩放梯度来缓解这个问题，但它本身也会因为 scale 过大而引发 inf。掌握 GradScaler 的调试技巧，能让你在混合精度训练中快速定位 NaN 根因，节省大量试错时间。

📝 一步步教你做

1

第1步：开启 GradScaler 的调试日志

在创建 GradScaler 时传入 init_scale 和 growth_interval 参数，并设置环境变量 TORCH_AMP_DEBUG=1 或使用 torch.cuda.amp.GradScaler(init_scale=2**16, growth_interval=100)。然后在 scaler.step(optimizer) 前后打印 scaler.get_scale()，观察 scale 是否频繁下降。如果 scale 持续下降，说明梯度频繁上溢，需要降低初始 scale。
💡 小贴士：先用较小的 init_scale（如 2**12）跑几百步，确认稳定后再逐步调大。
2

第2步：定位 NaN 出现的具体迭代和层

在训练循环中加入条件判断：if not torch.isfinite(loss): print(f'NaN at step {step}') 并保存当前 batch 数据。然后使用 torch.autograd.set_detect_anomaly(True) 包裹前向和反向传播，PyTorch 会打印出产生 NaN 的具体算子。结合 scaler.unscale_(optimizer) 后检查各参数梯度是否有限，快速缩小问题范围。
💡 小贴士：set_detect_anomaly 会显著拖慢训练，只在复现 NaN 的短循环中开启。
3

第3步：检查梯度裁剪与 GradScaler 的配合

混合精度下必须先调用 scaler.unscale_(optimizer) 再执行 torch.nn.utils.clip_grad_norm_，否则裁剪的是被放大后的梯度，导致裁剪失效或误判。确认代码顺序为：scaler.scale(loss).backward() → scaler.unscale_(optimizer) → clip_grad_norm_ → scaler.step(optimizer) → scaler.update()。顺序错误是 NaN 的常见诱因。
💡 小贴士：用 scaler.get_scale() 在 unscale 前后打印，确认梯度数值范围是否合理。
4

第4步：调整 GradScaler 参数并加入跳过机制

如果 NaN 偶发，可设置 scaler = GradScaler(init_scale=2**14, growth_factor=1.5, backoff_factor=0.5, growth_interval=2000)。当 scaler.step 检测到 inf 时会自动跳过该步并降低 scale，但你需要用 scaler.update() 后检查 scaler.get_scale() 是否骤降。若骤降频繁，说明模型对 fp16 敏感，可对部分层（如 LayerNorm）保留 fp32。
💡 小贴士：在 scaler.update() 后加一行 if scaler.get_scale() < 1: print('scale too low, check model') 作为预警。
5

第5步：用最小复现脚本验证修复效果

将出问题的 batch 数据固定下来，写一个最小循环：只跑该 batch 的前向+反向，重复 100 次，观察 loss 和 scale 变化。修复后应看到 loss 稳定下降、scale 不再持续下降、无 NaN 输出。最后把修复逻辑合并回主训练脚本，跑完整 epoch 确认。
💡 小贴士：保存修复前后的 scaler.get_scale() 曲线对比图，便于复盘。

✨ 完成后你会得到

训练过程中 loss 正常下降，scaler.get_scale() 保持稳定或缓慢增长，不再出现 NaN 或 inf；若偶发上溢，scaler 能自动降 scale 并跳过该步，训练继续。你能明确知道 NaN 来自哪一层或哪个操作，并有针对性地修复。

❓ 常见问题

GradScaler 的 scale 一直下降怎么办？ ▼
说明梯度频繁上溢，先降低 init_scale（如 2**12），检查是否有梯度爆炸，并确认 unscale_ 在 clip 之前调用。
为什么加了 GradScaler 反而出现 NaN？ ▼
常见原因是 scale 过大导致梯度上溢，或 unscale_ 与 clip 顺序错误。用 set_detect_anomaly 定位具体算子。
所有层都需要 fp16 吗？ ▼
不是。LayerNorm、softmax、loss 计算等对数值敏感的操作建议保留 fp32，可用 torch.cuda.amp.autocast 的 enabled=False 局部关闭。
CPU 上能用 GradScaler 吗？ ▼
GradScaler 主要针对 CUDA fp16，CPU 上混合精度支持有限，建议在 GPU 上使用。
如何判断是下溢还是上溢？ ▼
下溢时梯度变 0，loss 不降但无报错；上溢时梯度变 inf，scaler 会降 scale。打印 unscale 后的梯度范数可区分。

🚀 进阶玩法

  • 🔹 变体1：用 torch.cuda.amp.GradScaler 配合 torch.autograd.detect_anomaly 做自动化 NaN 捕获脚本，每次 NaN 自动保存 batch 和模型状态。
  • 🔹 变体2：对模型不同子模块设置不同的 autocast 策略（如 embedding 用 fp32，线性层用 fp16），再用 GradScaler 统一管理，降低 NaN 概率。
  • 🔹 变体3：将 GradScaler 的 scale 变化记录到 TensorBoard，结合梯度范数曲线做可视化监控，提前预警数值不稳定。
