📝 一步步教你做

1

第1步：初始化项目与安装依赖

创建新目录并初始化 npm 项目，安装 openai、dotenv、tsx 等依赖。配置 tsconfig.json 启用 ES 模块和严格模式。在 .env 文件中填入 OPENAI_API_KEY。
💡 小贴士：使用 pnpm 或 yarn 可以更快安装依赖；记得将 .env 加入 .gitignore。
2

第2步：定义工具接口与实现三个基础工具

创建一个 Tool 接口，包含 name、description、parameters（JSON Schema）和 execute 方法。实现三个工具：search（模拟搜索，返回固定结果）、calculate（用 eval 安全执行数学表达式）、readFile（读取指定路径的文件内容）。每个工具都要有清晰的描述，方便模型理解何时调用。
💡 小贴士：工具描述要具体，比如“计算数学表达式，支持加减乘除和括号”，这样模型才能准确选择工具。
3

第3步：构建 Agent 核心循环

编写一个 runAgent 函数，接收用户消息和工具列表。调用 OpenAI 的 chat.completions.create，传入 tools 参数。解析响应中的 tool_calls，依次执行对应工具，将结果以 role: 'tool' 的消息追加到对话历史中，再次调用模型，直到模型不再请求工具调用为止。
💡 小贴士：设置最大循环次数（如 10 次）防止无限调用；每次工具执行后打印日志便于调试。
4

第4步：编写命令行交互入口

使用 readline 模块创建交互式命令行，循环读取用户输入，调用 runAgent 并打印最终回复。支持多轮对话，维护一个全局 messages 数组保存上下文。
💡 小贴士：可以添加 /clear 命令清空对话历史，方便测试不同场景。
5

第5步：测试与调试

运行程序，尝试输入“帮我搜索 Node.js 22 的新特性”、“计算 (3+5)*2”、“读取 package.json 文件内容”等指令，观察 Agent 是否正确调用工具并整合结果。根据日志调整工具描述或参数定义。
💡 小贴士：如果模型不调用工具，检查 tools 参数格式是否正确；如果调用错误工具，优化工具描述。
6

第6步：接入 MCP 生态（可选扩展）

参考 MCP 协议文档，将工具实现为 MCP Server，通过 stdio 或 HTTP 与 Agent 通信。这样你的 Agent 就能动态发现和调用外部工具，无需硬编码。
💡 小贴士：先从官方 MCP 示例开始，逐步替换自己的工具，保持兼容性。

✨ 完成后你会得到

命令行中启动 Agent 后，输入自然语言指令，Agent 能自动判断是否需要调用工具，并返回整合后的答案。例如输入“搜索 Node.js 22 并计算 2 的 10 次方”，Agent 会先调用 search 工具，再调用 calculate 工具，最后汇总结果输出。

❓ 常见问题

没有 OpenAI API Key 怎么办？ ▼
可以使用兼容 OpenAI 接口的本地模型（如 Ollama + OpenAI 兼容层），或申请免费额度的其他平台（如 Groq、DeepSeek）。
工具调用总是失败或格式错误？ ▼
检查 tools 参数的 JSON Schema 是否符合 OpenAI 规范，确保每个工具都有 name、description 和 parameters 字段，且 parameters 是合法的 JSON Schema 对象。
如何让 Agent 支持更多工具？ ▼
按照 Tool 接口实现新的工具类，并在工具列表中注册即可。工具描述越清晰，模型选择越准确。
Agent 陷入循环调用怎么办？ ▼
在 runAgent 中设置最大迭代次数（如 10 次），超过后强制返回当前结果或提示用户。
这个 Agent 能用于生产环境吗？ ▼
可以作为原型，但生产环境需要增加错误处理、日志、限流、安全校验（如文件读取路径限制）等。

🚀 进阶玩法

  • 🔹 变体1：将工具调用改为并行执行——当模型一次返回多个 tool_calls 时，用 Promise.all 并发执行，提升效率。
  • 🔹 变体2：增加记忆功能——将对话历史持久化到 SQLite 或 Redis，实现跨会话记忆。
  • 🔹 变体3：接入真实搜索 API——用 SerpAPI 或 Bing Search API 替换模拟搜索工具，让 Agent 能获取实时信息。

手搓 Agent 的精髓在于理解“模型决策 + 工具执行”的循环，用最小依赖实现最大灵活性。
