🎯 为什么值得玩

作者在用 DeepSeek Harness（模型 GLM5.3）开发基于 ComfyUI 的动漫制作软件时，每次修改前端后 app.js 都会神秘消失。起初只是让 Agent 补文件，但反复出现后意识到必须根治。这个玩法展示了如何把 AI 编程 Agent 当作“结对调试员”，通过对话引导它阅读代码、分析文件操作逻辑、定位根因并给出修复方案，适合所有遇到偶发文件丢失、构建产物被误删等问题的开发者。

📝 一步步教你做

1

第1步：复现并记录文件消失现象

在修改前端代码后，立即检查 app.js 是否存在，记录消失前后的操作序列（如保存了哪个文件、执行了什么命令、是否触发了构建）。把现象整理成一段清晰的描述，包括出现频率和已尝试的临时补救措施。
💡 小贴士：用 git status 或文件监视工具确认文件是“被删除”还是“被重命名/移动”，这决定后续排查方向。
2

第2步：向 AI Agent 描述问题并给出上下文

在 DeepSeek Harness 中打开项目，向 Agent 说明：“每次修改前端后 app.js 会消失，已出现多次，请阅读项目代码找出原因”。把复现步骤、项目结构、相关配置文件路径一并提供，让 Agent 有足够上下文。
💡 小贴士：不要只说“文件没了”，要给出“修改前端→保存→app.js 消失”的因果链，Agent 定位会快很多。
3

第3步：引导 Agent 阅读代码并搜索文件操作

让 Agent 重点检查项目中所有涉及文件删除、重命名、构建清理的逻辑，例如 fs.unlink、rimraf、clean 脚本、webpack/vite 插件、文件监听器。要求它列出可疑代码位置并解释触发条件。
💡 小贴士：可以追加提示：“请搜索所有删除文件的调用，并说明在什么操作下会被触发”，避免 Agent 泛泛而谈。
4

第4步：让 Agent 给出根因假设与验证方法

要求 Agent 基于代码阅读结果，给出最可能的根因假设，并设计一个最小验证实验（如临时注释掉某段清理逻辑、加日志打印删除调用栈）。按建议执行验证，确认是否复现消失。
💡 小贴士：让 Agent 输出“假设→验证→结论”的表格，排查过程会更清晰，也方便回滚。
5

第5步：实施修复并让 Agent 复查

根据确认的根因修改代码（如调整清理脚本的匹配规则、修复文件监听误删逻辑），然后让 Agent 复查修改是否引入新风险。最后重复第1步的复现操作，确认 app.js 不再消失。
💡 小贴士：修复后让 Agent 生成一段回归测试或检查清单，防止同类问题再次出现。

✨ 完成后你会得到

AI Agent 定位到导致 app.js 被删除的具体代码逻辑（如构建清理脚本误匹配、文件监听器误删），给出修复方案；修改后反复修改前端，app.js 稳定存在，问题彻底解决。

❓ 常见问题

AI Agent 读不懂整个项目怎么办？ ▼
先缩小范围，只把与文件操作相关的目录和配置文件提供给 Agent，或让它分模块阅读，避免一次性塞入过多代码。
Agent 给出的根因不确定，如何判断？ ▼
要求 Agent 设计最小验证实验，通过注释代码、加日志、打印调用栈等方式实际验证，不要直接采信假设。
文件消失但 Agent 找不到删除调用怎么办？ ▼
检查是否有外部工具（如杀毒软件、同步盘、IDE 插件）或系统级清理任务，让 Agent 分析项目外的可能性，并用文件监视工具抓现场。
这个玩法只能用于文件消失问题吗？ ▼
不是，任何偶发、难以复现的 bug 都可以用同样的“描述现象→提供上下文→引导搜索→假设验证→修复复查”流程。

🚀 进阶玩法

  • 🔹 变体1：用 AI Agent 排查构建产物被误删问题——把“app.js 消失”换成“dist 目录被清空”，流程完全复用。
  • 🔹 变体2：让 Agent 自动生成文件操作审计脚本——在项目中加入日志埋点，记录所有删除/重命名调用，便于后续排查。
  • 🔹 变体3：把排查过程整理成团队 SOP——将 Agent 的假设验证表沉淀为调试模板，用于其他偶发 bug 的排查。

💡 一句话总结

把 AI 编程 Agent 当作结对调试员，用“现象描述+上下文+引导搜索+假设验证”的闭环，把玄学文件消失问题变成可定位、可修复的工程问题。
