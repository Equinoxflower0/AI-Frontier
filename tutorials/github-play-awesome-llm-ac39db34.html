第1步：克隆或收藏仓库，建立本地索引

打开 https://github.com/Hannibal046/Awesome-LLM ，点击右上角 Star 收藏。如果习惯本地查阅，可以用 git clone https://github.com/Hannibal046/Awesome-LLM.git 把整个仓库拉到本地。README.md 就是主清单，建议用 VS Code 或 Typora 打开，方便全文搜索。
💡 小贴士：Star 后可以在 GitHub 个人主页的 Stars 列表快速找到，同时关注 Releases 或 Watch 仓库，获取更新通知。
2

第2步：用目录锚点快速定位目标分类

README 开头有 Table of Contents，包含 Large Language Model、LLM Training、LLM Inference、LLM Evaluation、LLM Applications 等大类。先根据你的需求点击对应锚点跳转，比如想找开源模型就点“Large Language Model”，想找部署工具就点“LLM Inference”。每个分类下都有简短说明和链接，避免盲目滚动。
💡 小贴士：在 GitHub 页面按 T 键可以快速调出文件搜索框，输入关键词如“Llama”或“RAG”直接过滤。
3

第3步：按“模型-工具-数据-评测”四层筛选资源

建议用四层框架来筛选：第一层看基础模型（如 Llama、Qwen、DeepSeek），第二层看微调与推理工具（如 vLLM、SGLang、LLaMA-Factory），第三层看数据集与评测（如 MMLU、OpenCompass），第四层看应用与课程。每层挑 2-3 个最活跃的项目，记录到 Notion 表格中，字段包括名称、链接、Star 数、最近更新、适用场景。
💡 小贴士：优先选择最近 3 个月有 commit 的项目，Star 数高但长期不更新的项目可能已过时。
4

第4步：验证资源可用性，做最小化测试

对筛选出的工具或模型，不要只看介绍。打开其 GitHub 仓库，查看 README 的 Quick Start，尝试在本地或 Colab 跑一个最小 demo。例如对 vLLM，可以按官方命令安装并加载一个小模型；对 LLaMA-Factory，可以跑一次 LoRA 微调示例。验证通过后再纳入你的技术选型清单。
💡 小贴士：如果本地环境受限，优先用 Google Colab 或 Kaggle Notebook 做快速验证，避免环境配置卡住。
5

第5步：建立个人 Awesome-LLM 子清单并持续更新

在 Notion 或飞书里建一个“我的 Awesome-LLM”页面，按你的项目需求分类，比如“文本生成”“多模态”“Agent”“部署”。每周花 10 分钟浏览原仓库的 Recent Updates 或 Commits，把新出现的优质资源补充进去。也可以 Fork 原仓库，在本地维护自己的分支，添加注释和评分。
💡 小贴士：给每个资源打上“已测试/待测试/不适用”标签，避免重复调研。

❓ 常见问题

Awesome-LLM 和普通 GitHub 搜索有什么区别？ ▼
它由社区人工筛选和分类，覆盖全链路且持续更新，比通用搜索更精准、更省时间，尤其适合快速建立全局认知。
清单里的项目太多，如何避免选择困难？ ▼
先明确你的场景（如推理加速、微调、评测），再按“模型-工具-数据-评测”四层各选 2-3 个，用最小 demo 验证后再深入。
需要编程基础吗？ ▼
浏览和筛选不需要，但验证工具和模型时需要基本的 Python 和命令行操作。如果只想了解趋势，可以只看模型和论文部分。
如何知道某个资源是否还活跃？ ▼
看 GitHub 仓库的最近 commit 时间、issue 回复速度和 release 频率。一般最近 1-3 个月有更新的项目更可靠。
可以贡献自己的项目到 Awesome-LLM 吗？ ▼
可以。按照仓库的 Contributing 指南提交 PR，通常需要项目与 LLM 相关、有一定质量且持续维护。
