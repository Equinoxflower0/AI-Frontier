🎯 为什么值得玩

很多团队已经攒好了测评集、指标和评分器，但这些资产还停留在文档和脑子里，无法批量跑起来。要交给老板一份可信的评测报告，中间缺的正是执行链路：题怎么批量发、结果怎么逐条判、分数怎么汇总。本玩法以 LlamaIndex 构建的 RAG Agent 为被测对象，用 Promptfoo 做批量 Prompt 评测，DeepEval 做指标计算，LangSmith 做全链路追踪，三者拼成一条可复用的评测流水线。

📝 一步步教你做

1

第1步：准备测评集与 Agent 入口

把测评集整理成 JSONL 格式，每行包含 question 和 ground_truth 两个字段。同时用 LlamaIndex 把 RAG Agent 封装成一个可调用的函数，输入问题返回答案和检索到的上下文。确保这个函数不依赖交互式环境，能被脚本批量调用。
💡 小贴士：测评集先放 20-50 条即可跑通链路，后续再扩充；Agent 函数记得返回 context，DeepEval 算忠实度时要用。
2

第2步：用 Promptfoo 批量跑 Prompt 评测

在项目根目录创建 promptfooconfig.yaml，配置 prompts（你的提示词模板）、providers（模型或自定义脚本）和 tests（引用测评集）。运行 npx promptfoo eval 批量发送问题并收集回答。Promptfoo 会自动生成对比表格，方便你快速看不同提示词版本的差异。
💡 小贴士：如果 Agent 不是纯 Prompt 调用，可以用 Promptfoo 的 custom provider 指向你的 Python 脚本，保持评测入口统一。
3

第3步：用 DeepEval 逐条计算指标

安装 deepeval 后，编写脚本读取 Promptfoo 的输出结果，对每条样本构造 LLMTestCase，填入 input、actual_output、retrieval_context 和 expected_output。调用 FaithfulnessMetric、AnswerRelevancyMetric 等指标逐条打分，最后汇总成 CSV 或 JSON 报告。
💡 小贴士：DeepEval 默认用 OpenAI 做裁判，可以在脚本里设置 model 参数换成其他兼容模型，降低成本。
4

第4步：接入 LangSmith 追踪全链路

设置环境变量 LANGCHAIN_TRACING_V2=true 和 LANGCHAIN_API_KEY，在 Agent 调用外层加上 @traceable 装饰器或使用 LangSmith SDK 手动上报。这样每次评测的输入、检索、生成和评分都会形成一条可回放的 trace，方便定位是检索错还是生成错。
💡 小贴士：给每次评测运行打上 run_name 和 metadata（如 prompt 版本号），后续在 LangSmith 里按标签筛选对比。
5

第5步：汇总报告并固化流水线

写一个汇总脚本，把 Promptfoo 的通过率、DeepEval 的各项平均分和 LangSmith 的 trace 链接合并成一份 Markdown 报告。把整个流程封装成 make eval 或 GitHub Actions 工作流，每次改 Prompt 或换模型自动跑一遍，报告自动归档。
💡 小贴士：报告里保留每次运行的配置快照（模型、提示词版本、测评集版本），否则分数变化无法归因。

✨ 完成后你会得到

运行完整流水线后，你会得到一份包含每条样本回答、各项指标分数、平均分和 LangSmith trace 链接的评测报告。Promptfoo 的对比表格能直观看到提示词版本差异，DeepEval 给出量化分数，LangSmith 让你能点开任意一条失败案例回放整个执行过程。

❓ 常见问题

Promptfoo、DeepEval、LangSmith 三者功能有重叠，必须都用吗？ ▼
不是必须。Promptfoo 强在批量 Prompt 对比，DeepEval 强在指标计算，LangSmith 强在链路追踪。可以按需组合，比如只用 Promptfoo + DeepEval 也能出报告，LangSmith 用于排障。
没有 OpenAI API Key 能跑吗？ ▼
可以。Promptfoo 和 DeepEval 都支持自定义 provider 或兼容 OpenAI 接口的模型服务，LangSmith 也支持自托管版本。把模型端点配成你的本地或第三方服务即可。
测评集很小，分数波动大怎么办？ ▼
先保证测评集覆盖核心场景，每条样本可多次运行取平均；同时固定模型版本和温度参数，减少随机性。样本量建议逐步扩到 100 条以上再用于决策。
LangSmith 的 trace 会不会包含敏感数据？ ▼
会，默认会上报输入输出。生产环境建议开启脱敏或使用自托管 LangSmith，并在上报前过滤掉用户隐私字段。

🚀 进阶玩法

  • 🔹 变体1：把 Promptfoo 换成自写批量脚本，只保留 DeepEval + LangSmith，适合已有成熟评测框架的团队。
  • 🔹 变体2：在 CI 中加阈值门禁，DeepEval 平均分低于基线时自动失败，防止 Prompt 改动导致效果回退。
  • 🔹 变体3：用 LangSmith 的 dataset 功能管理测评集，直接在平台内发起评测并与 trace 关联，减少本地脚本维护。
