🎯 为什么值得玩

Chrome 团队推出的 Modern Web Guidance 是一个面向 AI 编码助手的前端规范检索包，旨在让 AI 在生成代码时能引用最新、最准确的 Web 平台特性。掘金作者实测发现：离线检索仅需 0.77 秒，fallback 能精确到版本；但扫描器首轮 0 命中，守卫按文件砍，发布包 35 条而源码已有 51 条；此外 telemetry 默认外发搜索词，需注意隐私。这个玩法适合正在搭建 AI 编码助手、需要注入前端规范知识库的开发者，也适合想了解 AI 检索包设计思路的技术爱好者。

💡 小贴士：建议在 CI 或团队共享环境中默认关闭 telemetry，避免搜索词泄露内部项目信息。

💡 小贴士：可以先在低风险场景（如内部工具页面）试用一周，收集 bad case 再决定是否全量接入。

❓ 常见问题

离线检索 0.77 秒算快吗？能用于实时 AI 编码场景吗？ ▼
0.77 秒对于单次检索可以接受，但如果 AI 每生成一段代码都调用一次，累积延迟会明显。建议做结果缓存或批量检索，把多次查询合并为一次。
扫描器首轮 0 命中是 bug 吗？ ▼
不是 bug，通常是索引未建立或缓存为空导致。首轮扫描用于预热，第二轮开始才有命中。可以在启动时主动触发一次预热扫描。
发布包 35 条但源码 51 条，少的 16 条去哪了？ ▼
发布包会按规则裁剪，可能排除了实验性规范、重复条目或未达到稳定版本的特性。具体裁剪逻辑需查看构建脚本中的 filter 规则。
telemetry 默认外发搜索词，会不会泄露代码？ ▼
默认会上报搜索词，可能包含你查询的前端特性名。如果查询词涉及内部项目代号，存在泄露风险。建议关闭 telemetry 或设置 DO_NOT_TRACK=1。
这个检索包能直接给 Cursor / Copilot 用吗？ ▼
不能直接插拔，需要自己封装成工具调用或 MCP server。检索包本身是数据+检索逻辑，AI 助手需要能主动调用它才能发挥作用。

🚀 进阶玩法

  • 🔹 变体1：将检索包封装为 MCP Server，让 Claude Desktop 或 Cursor 通过 MCP 协议直接调用，实现前端规范实时检索。
  • 🔹 变体2：把检索包与 ESLint 结合，在代码提交前自动检索相关规范并生成提示，形成「检索+校验」双保险。
  • 🔹 变体3：定期对比源码与发布包差异，自动生成「新增规范」报告，推送到团队群，保持前端知识库同步更新。
