1

第1步：精读四场分享，提炼 Agent 构建与治理的关键要素

打开掘金教程原文，通读阿里云四场分享的摘要与案例，重点记录每场分享的核心观点：Agent 设计模式（如 ReAct、Plan-and-Execute）、工具调用与函数注册方式、多智能体协作拓扑、以及治理层面的权限控制与可观测性。建议用表格整理「分享主题—关键方法—可复用点」三列，形成自己的知识地图。
💡 小贴士：优先关注带有代码片段或架构图的分享，这些内容最容易转化为可运行的实现。
2

第2步：在阿里云百炼平台创建基础 Agent 并配置工具

登录阿里云百炼控制台，进入「智能体应用」页面，点击创建智能体。选择通义千问作为基础模型，在「工具」选项卡中启用至少两个内置工具（如天气查询、网页搜索），并配置一个自定义函数工具（例如查询当前时间）。在「提示词」区域编写系统指令，明确 Agent 的角色、可用工具和输出格式。保存后使用平台内置的调试窗口进行对话测试。
💡 小贴士：系统提示词中显式列出工具名称和调用条件，能显著降低模型乱调用工具的概率。
3

第3步：用 DashScope SDK 在本地复现一个 ReAct 风格 Agent

安装 dashscope SDK（pip install dashscope），设置环境变量 DASHSCOPE_API_KEY。编写一个 Python 脚本，定义两个本地函数（如 get_weather 和 search_web），并将函数描述以 JSON Schema 形式注册到模型调用参数中。实现一个循环：模型返回工具调用请求时，本地执行对应函数并将结果回传给模型，直到模型输出最终答案。运行脚本，测试「北京今天天气如何，适合户外运动吗」这类需要多步推理的问题。
💡 小贴士：在循环中设置最大迭代次数（如 5 次），防止 Agent 陷入无限工具调用。
4

第4步：引入治理机制——日志、权限与人工审核点

在本地 Agent 脚本中加入结构化日志，记录每次模型输入、工具调用参数和返回结果。为工具函数增加权限校验装饰器，例如只允许查询白名单内的 API。在关键操作（如发送邮件、修改数据）前插入人工确认步骤，通过命令行输入 y/n 决定是否继续。参考分享中提到的治理框架，整理一份 Agent 治理检查清单。
💡 小贴士：日志建议输出为 JSON Lines 格式，方便后续用 jq 或日志平台做审计分析。
5

第5步：对比分享中的多智能体协作模式，扩展一个双 Agent 协作 Demo

基于第 3 步的代码，拆分出两个角色：一个「规划 Agent」负责拆解任务，一个「执行 Agent」负责调用工具完成子任务。规划 Agent 输出 JSON 格式的任务列表，执行 Agent 逐条处理并汇总结果。用简单的消息队列（如 Python queue）在两者之间传递消息。运行并观察协作效果，记录与单 Agent 模式在准确率和耗时上的差异。
💡 小贴士：两个 Agent 使用不同的系统提示词，并限制各自可用的工具集，能减少职责混淆。
